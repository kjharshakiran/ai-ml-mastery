The Big Question
Nobody ever showed you the "correct" move for every chess position — yet you can learn to play. How can a machine learn good behaviour from nothing but the occasional reward, with no labelled answer key at all?

40.1 A third way to learn

Back in Weeks 11–12 we sorted machine learning into paradigms. Supervised learning needs a teacher: every input comes with the right answer (this email is spam). Unsupervised learning has no answers at all, just structure to find (group these customers). Reinforcement learning (RL) is a genuinely different third way: there's no answer key, only a stream of rewards — numbers that say "that was good" or "that was bad" — and the agent must learn, by trial and error, which actions earn the most reward over time.

The twist that makes RL hard and beautiful: rewards can be delayed. A chess move that loses the game might look fine for twenty moves. The agent must learn to credit (or blame) decisions made long before the payoff arrived. This is the credit assignment problem, and it's the heart of RL.

🧒 Explain Like I'm 10

Think about learning to ride a bike. Nobody hands you a sheet saying "lean exactly 4 degrees left now." You just try — wobble, fall (bad reward), stay up for three seconds (good reward), try again. Slowly your body learns which little moves keep you upright. Reinforcement learning is teaching a computer to learn the bike-riding way: by trying, getting a thumbs-up or thumbs-down, and getting better.

40.2 The RL framework: the interaction loop

Every RL problem is built from the same five pieces, locked in a loop:

  • Agent — the learner and decision-maker (the chess player, the robot, the trading bot).
  • Environment — everything outside the agent that it acts upon (the chessboard, the physical world).
  • State \(s\) — a snapshot of the situation right now (the board position).
  • Action \(a\) — a move the agent can make (move a pawn).
  • Reward \(r\) — the scalar feedback the environment gives back (+1 for a win, 0 otherwise).

At each time step \(t\): the agent observes state \(s_t\), chooses an action \(a_t\), and the environment responds with a reward \(r_{t+1}\) and a new state \(s_{t+1}\). Then it all repeats. The agent's goal is to learn a policy \(\pi(a \mid s)\) — a strategy mapping states to actions — that maximises the total reward it collects over time.

40.3 Markov Decision Processes

To do mathematics on this loop we formalise it as a Markov Decision Process (MDP), the bedrock of all RL. An MDP is five things:

  • A set of states \(S\) and a set of actions \(A\).
  • Transition probabilities \(P(s' \mid s, a)\) — the chance of landing in \(s'\) after taking action \(a\) in state \(s\). The world can be stochastic.
  • A reward function \(R(s, a)\) — the reward for that move.
  • A discount factor \(\gamma \in [0, 1)\) — how much we value future reward versus immediate reward.

The defining assumption is the Markov property: the future depends only on the current state, not the entire history of how you got there. The current state captures everything relevant. (A chess position tells you all you need; you don't need the move list.)

The return. The agent doesn't maximise the next reward — it maximises the total discounted future reward, called the return \(G_t\):

\[ G_t = r_{t+1} + \gamma\, r_{t+2} + \gamma^2 r_{t+3} + \cdots = \sum_{k=0}^{\infty} \gamma^{k}\, r_{t+k+1} \]

The discount \(\gamma\) (say 0.9) makes a reward 10 steps away worth \(0.9^{10}\approx 0.35\) of one right now — it values the present, and keeps the sum finite for endless tasks.

💰 Real-World Analogy

The discount factor is the interest rate of patience. A dollar today is worth more than a dollar next year, because the future is uncertain and money now can be used now. \(\gamma\) close to 1 is a patient, far-sighted agent that plans for the long game; \(\gamma\) close to 0 is an impulsive agent that grabs whatever reward is closest. Tuning \(\gamma\) literally tunes how much your agent "saves for the future."

Value functions. How good is it to be in a state? The value function \(V^\pi(s)\) is the expected return you'll collect starting from state \(s\) and following policy \(\pi\) thereafter. The genius of RL is that values are self-referential: the value of a state equals the immediate reward plus the discounted value of wherever you land next. That recursion is the Bellman equation:

\[ V^\pi(s) = \sum_{a} \pi(a\mid s) \sum_{s'} P(s'\mid s,a)\Big[\, R(s,a) + \gamma\, V^\pi(s') \,\Big] \]

And the optimal value — the best any policy can do — replaces the policy average with a max over actions:

\[ V^*(s) = \max_{a} \sum_{s'} P(s'\mid s,a)\Big[\, R(s,a) + \gamma\, V^*(s') \,\Big] \]

This is the equation we'll iterate in code. Turn it into an update rule — repeatedly set each \(V(s)\) to the right-hand side using current estimates — and it provably converges to \(V^*\). That algorithm is value iteration.

🔑 The one equation to remember

The Bellman equation says: the value of now = the reward now + the discounted value of next. Every RL algorithm — value iteration, Q-learning, the deep RL behind AlphaGo — is, at its core, a clever way to solve or approximate this single recursive relationship.

40.4 A worked grid world

Let's make it concrete with the simplest possible world: a 1×4 corridor. The agent starts at the far left (state 0) and wants to reach the goal at state 3. Two actions: move left or right. Every step costs a reward of \(-1\) — so the agent is pushed to reach the goal as quickly as possible. State 3 is terminal (the episode ends there).

Now we solve it with value iteration — literally sweeping the Bellman optimality update until the values stop changing:

numpy — value iteration on a grid world
import numpy as np

# A 1x4 corridor of states 0,1,2,3. State 3 is the GOAL (terminal/absorbing).
# Actions: 0 = move left, 1 = move right. Every step costs -1 until the goal.
n_states, gamma, GOAL = 4, 0.9, 3

def step(s, a):
    """Environment dynamics: given state s and action a, return (next_state, reward)."""
    if s == GOAL:
        return s, 0.0                      # goal is absorbing: stay, no reward
    s_next = max(0, s - 1) if a == 0 else min(GOAL, s + 1)
    reward = 0.0 if s_next == GOAL else -1.0
    return s_next, reward

V = np.zeros(n_states)                      # value estimate of each state
for _ in range(100):                        # sweep the Bellman update to convergence
    V_new = V.copy()
    for s in range(n_states):
        if s == GOAL:
            continue
        # Bellman optimality: V(s) = max over actions of [ reward + gamma * V(next) ]
        V_new[s] = max(r + gamma * V[s2] for s2, r in (step(s, a) for a in (0, 1)))
    if np.max(np.abs(V_new - V)) < 1e-6:    # converged?
        break
    V = V_new

print("State values:", np.round(V, 2))      # -> [-1.9 -1.   0.   0.]

# Read off the greedy policy: the action with the highest Bellman value
arrows = []
for s in range(n_states):
    if s == GOAL:
        arrows.append("G"); continue
    q = [step(s, a)[1] + gamma * V[step(s, a)[0]] for a in (0, 1)]
    arrows.append("->" if np.argmax(q) == 1 else "<-")
print("Best policy:", " ".join(arrows))      # -> -> -> -> G  (always head right)

The values make sense: state 2 is one cheap step from the goal (\(-1\)), state 1 is two steps (\(-1.9\) after discounting), and the goal is \(0\). The derived policy is "always go right" — exactly what we'd expect. Scale this same loop up to a 2D maze, a robot, or a game, and you have the skeleton of real RL.

40.5 Beyond value iteration: Q-learning & RLHF

Value iteration needs to know the environment's transition probabilities \(P(s'\mid s,a)\). Often we don't — so the agent must learn purely from experience. Q-learning does exactly that: instead of state values \(V(s)\), it learns action-values \(Q(s,a)\) (how good is taking action \(a\) in state \(s\)?) directly from sampled transitions, with no model of the world. Pair Q-learning with a neural network to approximate \(Q\) and you get Deep Q-Networks — the method that learned to play Atari from raw pixels.

And here the whole course comes full circle. Remember RLHF — Reinforcement Learning from Human Feedback — from Week 34? That's RL in this exact framework: the agent is the language model, an action is generating a response, and the reward comes from a model trained on human preferences. The same Bellman-flavoured optimisation that solves a toy corridor is what nudges a giant LLM toward helpful, honest answers.

✅ Check Yourself

What most distinguishes reinforcement learning from supervised learning?
Supervised learning is handed the correct output for each input. RL gets only scalar rewards (good/bad), must discover good actions by trying them, and must handle rewards that arrive long after the actions that earned them — the credit-assignment problem.
In the return \(G_t = \sum_k \gamma^k r_{t+k+1}\), what does the discount factor \(\gamma\) control?
\(\gamma\) near 1 makes a far-sighted, patient agent that weighs distant rewards heavily; \(\gamma\) near 0 makes a short-sighted agent grabbing immediate reward. It also keeps the infinite sum finite for never-ending tasks.
The Bellman equation expresses which core idea?
Bellman's recursion ties each state's value to its successors: V(s) = reward now + γ·V(next). Iterating this update (value iteration) converges to the optimal values — and the same idea underpins Q-learning and deep RL.
