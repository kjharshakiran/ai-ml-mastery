Clustering: k-Means & Hierarchical

⏱️ 50 min🎯 Finding groups with no labels📦 Week 23

By the end of this lesson you'll be able to…

  • Explain clustering as unsupervised grouping by similarity.
  • Run the k-means loop: assign to nearest centroid → recompute centroids → repeat.
  • Tie the "nearest" decision to the distance/norm from Week 2.
  • Build a hierarchy with agglomerative (bottom-up) clustering and read a dendrogram.

The Big Question
Nobody has labelled your customers. Can a machine still discover that they naturally fall into "bargain hunters," "loyalists," and "big spenders" — entirely on its own?

1. Clustering: grouping without labels

Every model since Week 13 has been supervised — we handed it the right answers (labels) to learn from. Clustering is unsupervised (the paradigm from Week 11): there are no labels at all. The algorithm gets only the raw feature vectors and must discover structure by itself — grouping points so that members of a group are similar to each other and different from other groups.

It's used for customer segmentation, grouping documents by topic, compressing images, and spotting anomalies (a point that joins no cluster is suspicious). The key question, as always, is "what does similar mean?" — and the answer, as always, is distance.

🧒 Explain Like I'm 10

Picture a giant messy toy box. Nobody told you the categories, but you instinctively sort them into bins: cars here, blocks there, stuffed animals over there — putting things that look alike together. Clustering is a computer doing exactly that with data points: making bins of similar things, with no labels to guide it.

2. k-Means: the assign-and-update dance

k-means is the most-used clustering algorithm. You tell it how many groups \(k\) you want; it finds \(k\) centroids (cluster centres) and assigns every point to its nearest one. It minimises the total squared distance from points to their centroid — the inertia:

\[ J = \sum_{j=1}^{k} \sum_{\mathbf{x}\in C_j} \lVert \mathbf{x} - \boldsymbol{\mu}_j \rVert^{2} \]

where \(\boldsymbol{\mu}_j\) is the centroid of cluster \(C_j\), and that \(\lVert\cdot\rVert\) is precisely the norm from Week 2. It can't solve this in one shot, so it iterates a beautifully simple loop:

  1. Initialise: drop \(k\) centroids somewhere (often \(k\) random points).
  2. Assign: attach each point to the nearest centroid (smallest \(\lVert \mathbf{x}-\boldsymbol{\mu}_j\rVert\)).
  3. Update: move each centroid to the mean of the points now assigned to it.
  4. Repeat assign + update until nothing changes (the centroids settle).

Each round can only lower (or hold) the inertia, so it always converges — usually within a dozen iterations.

🔑 The one thing to remember

k-means alternates two steps forever: assign points to the nearest centroid, then move each centroid to its points' mean. "Nearest" is the Week 2 norm; "mean" is the average. Because distances drive everything, you must scale your features first (Week 19).

⚠️ Common Pitfall

You must choose \(k\) up front, and a bad starting position can trap k-means in a poor solution. Run it several times (scikit-learn's k-means++ init and n_init do this for you) and use the "elbow" of the inertia curve or a silhouette score to pick \(k\). k-means also assumes roughly round, equal-sized clusters — it struggles with stringy or nested shapes.

scikit-learn — KMeans on toy blobs
import numpy as np
from sklearn.datasets import make_blobs
from sklearn.preprocessing import StandardScaler
from sklearn.cluster import KMeans

# 300 points that really form 3 blobs (but we hide that from the model)
X, _ = make_blobs(n_samples=300, centers=3, random_state=42)
X = StandardScaler().fit_transform(X)        # Week 19: scale before distance-based clustering

km = KMeans(n_clusters=3, n_init=10, random_state=0)  # n_init: try 10 starts, keep the best
labels = km.fit_predict(X)                   # the assign/update loop, run to convergence

print("cluster sizes:", np.bincount(labels)) # roughly even -> 3 balanced groups
print("centroids:\n", km.cluster_centers_.round(2))
print("inertia (total squared distance):", round(km.inertia_, 1))

3. Hierarchical clustering: a family tree of groups

k-means makes you commit to \(k\) and gives a flat set of groups. Hierarchical clustering instead builds a whole tree of nested clusters, so you can choose how many groups you want afterwards by slicing the tree at the right height. The tree is drawn as a dendrogram. There are two directions to build it: bottom-up (agglomerative) and top-down (divisive).

4. Agglomerative: bottom-up merging

Agglomerative clustering starts with every point as its own tiny cluster, then repeatedly merges the two closest clusters until only one remains. The order of merges is the dendrogram. "Closest" depends on the linkage rule — how you measure distance between two groups:

  • Single linkage — distance between the two nearest members (makes long, chain-like clusters).
  • Complete linkage — distance between the two farthest members (makes tight, compact clusters).
  • Average linkage — average over all pairs.
  • Ward — merge the pair that increases total within-cluster variance the least (the common default).
🌳 Real-World Analogy

Agglomerative clustering is a family tree built backwards. Start with every individual, then keep pairing up the closest relatives — siblings join, then cousins, then whole branches — until everyone shares one ancestor. Cut the tree at any height to ask "how many family groups exist at this level of closeness?"

5. Divisive: top-down splitting

Divisive clustering runs the other way: start with all points in one big cluster and recursively split the least-cohesive cluster into two, again and again, until each point stands alone (or you stop early). It's conceptually the mirror image of agglomerative, but more expensive to compute, so agglomerative is far more common in practice. Both produce a dendrogram; they just build it from opposite ends.

scikit-learn — AgglomerativeClustering
import numpy as np
from sklearn.datasets import make_blobs
from sklearn.preprocessing import StandardScaler
from sklearn.cluster import AgglomerativeClustering

X, _ = make_blobs(n_samples=300, centers=3, random_state=42)
X = StandardScaler().fit_transform(X)

# Bottom-up merging with Ward linkage (minimises within-cluster variance)
agg = AgglomerativeClustering(n_clusters=3, linkage="ward")
labels = agg.fit_predict(X)
print("cluster sizes:", np.bincount(labels))  # 3 groups, no centroids needed

# Try different linkages to see how cluster shape changes
for link in ["ward", "complete", "average", "single"]:
    m = AgglomerativeClustering(n_clusters=3, linkage=link).fit(X)
    print(f"{link:<9} -> sizes {np.bincount(m.labels_)}")

✅ Check Yourself

What are the two repeating steps of the k-means algorithm?
k-means alternates assignment (nearest centroid by Week-2 distance) and update (recompute centroids as the mean). It repeats until the centroids stop moving, lowering total inertia each round.
How does agglomerative hierarchical clustering build its tree?
Agglomerative is bottom-up: start with singletons and merge the two nearest clusters (per the linkage rule) until one remains. That merge order is the dendrogram. Divisive is the top-down mirror image.
Why should you scale your features before running k-means?
k-means assigns points by Euclidean distance, so an unscaled big-range feature drowns out the others — exactly the Week 19 problem. Standardising first gives every feature a fair say in the clustering.
