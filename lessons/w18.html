SVM II: Margins, Kernels & the Kernel Trick

⏱️ 60 min🎯 The widest, safest boundary📦 Week 18

By the end of this lesson you'll be able to…

  • Explain the SVM idea: of all separating lines, pick the one with the widest margin.
  • Identify support vectors and why they alone define the boundary.
  • Use a soft margin (slack, the parameter C) when classes overlap.
  • Bend boundaries with feature maps, and apply the kernel trick (RBF, polynomial).
  • Handle more than two classes with one-vs-rest / one-vs-one.
The Big Question
The perceptron stops at any line that separates the data — even one that skims dangerously close to the points. But infinitely many lines separate two clusters. Which one is best, and how could we ever draw a straight boundary through data that's clearly not straight-separable?

1. The SVM idea: don't just separate — separate with room to spare

A Support Vector Machine (SVM) is a discriminative classifier (like last week's perceptron) with one powerful upgrade: among all the lines that split the two classes, it chooses the one that sits as far as possible from the nearest points on both sides. That cushion of empty space is the margin, and maximising it is what makes SVMs so robust on new data.

🧒 Explain Like I'm 10

Two crowds stand in a field and you must paint a line between them. You could paint it right next to one crowd — but then one wobble and someone's on the wrong side. The smart move is to paint it down the middle of the widest empty lane, as far from both crowds as possible. That widest lane is the SVM's margin.

2. The maximum-margin hyperplane

Picture the boundary as a street with two gutters touching the closest points of each class. The SVM finds the boundary that makes this street as wide as possible. With labels \(y_i\in\{-1,+1\}\), the width of the margin works out to \(2/\lVert\mathbf{w}\rVert\), so maximising the margin means minimising \(\lVert\mathbf{w}\rVert\) subject to every point sitting on the correct side of its gutter:

\[ \min_{\mathbf{w},b}\ \tfrac{1}{2}\lVert\mathbf{w}\rVert^2 \quad \text{subject to}\quad y_i(\mathbf{w}\cdot\mathbf{x}_i + b) \ge 1 \ \ \forall i \]

The handful of points that land exactly on the gutters are the support vectors. They are the only points that matter — delete every other point and the boundary doesn't move. That's why SVMs are memory-efficient and resistant to outliers far from the boundary.

🔑 The one thing to remember

The SVM margin is the widest safety gap between the two classes. A wide gap means the boundary is confident and generalises well; only the borderline points (support vectors) get a vote in where it goes.

3. Soft margins: when the classes overlap

Real data is messy — a few points stray into enemy territory and no straight line can separate them perfectly. The soft-margin SVM allows controlled violations using slack variables \(\xi_i \ge 0\) that measure how far each offender intrudes, penalised by a knob \(C\):

\[ \min_{\mathbf{w},b,\xi}\ \tfrac{1}{2}\lVert\mathbf{w}\rVert^2 + C\sum_i \xi_i \quad \text{s.t.}\quad y_i(\mathbf{w}\cdot\mathbf{x}_i+b)\ge 1-\xi_i \]

  • Large C — punishes mistakes hard → a narrow margin that bends to fit every point (risk: overfitting).
  • Small C — tolerates violations → a wider, smoother margin (risk: underfitting).

\(C\) is the bias–variance dial from Week 14, wearing an SVM costume. We tune it by cross-validation.

4. Nonlinear boundaries via feature maps

What about data shaped like a bullseye — one class ringed by the other? No line can split that in its native 2D. The fix: apply a feature map \(\phi(\mathbf{x})\) that lifts each point into a higher-dimensional space where the classes do become linearly separable. For a ring, adding the feature \(x_1^2 + x_2^2\) (distance from centre) lifts the inner class down and the outer class up — and a flat plane now slices between them.

5. The kernel trick: the lift without the climb

Here is the magic. The SVM only ever touches the data through dot products \(\mathbf{x}_i\cdot\mathbf{x}_j\). So in the lifted space it only needs \(\phi(\mathbf{x}_i)\cdot\phi(\mathbf{x}_j)\). A kernel \(K\) is a function that computes that high-dimensional dot product directly from the original points, without ever constructing \(\phi(\mathbf{x})\):

\[ K(\mathbf{x}_i,\mathbf{x}_j) = \phi(\mathbf{x}_i)\cdot\phi(\mathbf{x}_j) \]

The two most-used kernels:

  • Polynomial: \(K(\mathbf{x},\mathbf{z}) = (\mathbf{x}\cdot\mathbf{z} + c)^{d}\) — curved boundaries up to degree \(d\).
  • RBF / Gaussian: \(K(\mathbf{x},\mathbf{z}) = \exp(-\gamma\lVert\mathbf{x}-\mathbf{z}\rVert^2)\) — effectively an infinite-dimensional lift, the go-to default.

This is the famous kernel trick: we reap the power of an enormous (even infinite) feature space while only ever doing cheap computations on the original points.

The kernel trick in numbers

"Same dot product, no \(\phi\)" sounds like sleight of hand — so let's compute it both ways and check the answers match. Take two points and the degree-2 polynomial kernel \(K(\mathbf{x},\mathbf{z})=(\mathbf{x}\cdot\mathbf{z}+1)^2\).

VectorCoordinates
\(\mathbf{x}\)\((2,3)\)
\(\mathbf{z}\)\((1,4)\)

Step 1 — the cheap way (kernel). One dot product in the original 2D space: \(\mathbf{x}\cdot\mathbf{z} = 2\cdot 1 + 3\cdot 4 = 14\). Then

\[ K(\mathbf{x},\mathbf{z}) = (14+1)^2 = 225 \]

Step 2 — the expensive way (build \(\phi\)). The matching feature map is \(\phi(a,b)=(a^2,\,b^2,\,\sqrt{2}\,ab,\,\sqrt{2}\,a,\,\sqrt{2}\,b,\,1)\), a lift into 6D. So \(\phi(\mathbf{x})=(4,9,8.485,2.828,4.243,1)\) and \(\phi(\mathbf{z})=(1,16,5.657,1.414,5.657,1)\). Their dot product:

\[ \phi(\mathbf{x})\cdot\phi(\mathbf{z}) = 4 + 144 + 48 + 4 + 24 + 1 = 225 \]

Identical — \(225\) either way, but the kernel reached it with a single 2D dot product instead of building and multiplying six coordinates. The RBF kernel does the same for an infinite-dimensional \(\phi\): for \(\mathbf{x}=(1,0)\), \(\mathbf{z}=(0,1)\), \(\gamma=0.5\), we get \(\lVert\mathbf{x}-\mathbf{z}\rVert^2=2\) so \(K=e^{-0.5\cdot 2}=e^{-1}\approx 0.368\) (and identical points give \(K=e^0=1\)).

🔑 The kernel is the lifted dot product

A kernel isn't an approximation or a shortcut that loses something — \(K(\mathbf{x},\mathbf{z})\) returns the exact dot product \(\phi(\mathbf{x})\cdot\phi(\mathbf{z})\) in the high-dimensional space, paid for at original-space cost. That's why an RBF SVM can work in infinite dimensions without ever storing a single lifted coordinate.

📄 Real-World Analogy

Imagine red and blue dots tangled on a flat sheet of paper, impossible to separate with scissors in one straight cut. Now crumple the paper into 3D — suddenly the reds float above the blues, and a single flat slice separates them. The kernel trick is computing the result of that crumpling using only measurements you can take on the flat page — you never actually crumple anything.

scikit-learn — linear vs RBF SVC
import numpy as np
from sklearn.datasets import make_circles
from sklearn.model_selection import train_test_split
from sklearn.svm import SVC
from sklearn.metrics import accuracy_score

# Bullseye data: inner ring vs outer ring — NOT linearly separable
X, y = make_circles(n_samples=300, factor=0.4, noise=0.1, random_state=0)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=0)

# A linear kernel cannot bend around the ring
lin = SVC(kernel="linear", C=1.0).fit(X_tr, y_tr)
print("linear  acc:", round(accuracy_score(y_te, lin.predict(X_te)), 2))  # ~0.5

# The RBF kernel lifts to an infinite-dim space — a circle becomes "linear"
rbf = SVC(kernel="rbf", C=1.0, gamma="scale").fit(X_tr, y_tr)
print("rbf     acc:", round(accuracy_score(y_te, rbf.predict(X_te)), 2))  # ~1.0

# Support vectors are the only points that define the boundary
print("num support vectors:", rbf.n_support_)   # one count per class

6. More than two classes

An SVM natively draws one boundary, so for \(C\) classes we combine several:

  • One-vs-Rest (OvR): train \(C\) classifiers, each "class \(k\) vs everything else"; pick the most confident.
  • One-vs-One (OvO): train a classifier for every pair of classes and let them vote. scikit-learn's SVC uses OvO by default.
🔗 Connect the Dots

Kernels are nothing but dot products (Week 2) computed in a hidden high-dimensional space — the same similarity measure, supercharged. The SVM extends the discriminant boundary of Week 17 by demanding the widest margin, and you'll grade it with the precision/recall kit from Week 15. The maximum-margin SVM is the crowning classical classifier — the state of the art that reigned right up until the deep-learning era you'll enter in Week 24.
