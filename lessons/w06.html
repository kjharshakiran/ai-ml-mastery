The Big Question
Every model, every dataset, every neural network you'll build is ultimately a few lines of Python. So what are the handful of building blocks — boxes, lists, lookups, loops, functions — that everything else is made of?

1. Variables: labelled boxes

A variable is a name attached to a value. In Python you don't declare a type — you just assign, and the name now refers to that value.

🧒 Explain Like I'm 10

A variable is a labelled box. You write age = 10 and now there's a box labelled age with the number 10 inside. Later you can peek in the box (use age), or swap what's inside (age = 11). The label never changes; the contents can.

python — the basic types
# Four everyday types. No type declarations needed.
name    = "Asha"      # str  — text, in quotes
age     = 31          # int  — whole number
spend   = 1650.50     # float— decimal number
is_vip  = True        # bool — True or False

# f-strings drop variables straight into text
print(f"{name} is {age} and a VIP: {is_vip}")
# -> Asha is 31 and a VIP: True

# Python knows the type for you
print(type(spend))    # -> <class 'float'>

2. The four core data structures

Single values are nice, but data science is about collections. Python gives you four, and choosing the right one is half of writing clean code. The deciding questions: is it ordered? can it change (mutable)? are duplicates allowed? do I look things up by position or by name?

python — the four collections
# LIST: ordered, changeable, allows duplicates. Your default container.
cart = ["pen", "notebook", "pen"]
cart.append("eraser")     # add to the end
print(cart[0])            # index by position -> 'pen'

# TUPLE: ordered but IMMUTABLE — use for fixed groups that shouldn't change
location = (19.07, 72.87) # (latitude, longitude) of Mumbai
# location[0] = 0         # would raise TypeError: tuples can't be changed

# SET: unordered, no duplicates. Great for "have I seen this?" and dedup.
unique_items = set(cart)  # -> {'pen', 'notebook', 'eraser'}  (dupes gone)
print("pen" in unique_items)   # membership test is very fast -> True

# DICT: maps keys to values. The workhorse of Python — look up by name.
customer = {"name": "Asha", "age": 31, "city": "Mumbai"}
print(customer["city"])        # -> Mumbai
customer["spend"] = 1650       # add a new key:value pair
🔑 Mutability — the trap behind half of all beginner bugs

Lists, sets and dicts are mutable: you can change them in place. Tuples and strings are immutable: once made, they're frozen. Why care? Two variables can point at the same mutable list, so changing one changes "both." Use a tuple when you want a guarantee that a value won't be altered behind your back — like a fixed (lat, long) coordinate.

3. Loops & conditionals: doing something to each item

A for loop walks through a collection one item at a time. An if statement makes a decision. Together they let you process data.

python — loops & comprehensions
prices = [120, 45, 300, 89]

# A for-loop with an if: sum only the "big" purchases
big_total = 0
for p in prices:
    if p >= 100:          # the condition
        big_total += p    # runs only when condition is True
print(big_total)          # -> 420  (120 + 300)

# A list comprehension: the Pythonic one-liner for "transform each item"
with_tax = [p * 1.18 for p in prices]   # add 18% tax to every price
print(with_tax)           # -> [141.6, 53.1, 354.0, 105.02]

# Comprehension with a filter: keep only items that pass the condition
big = [p for p in prices if p >= 100]   # -> [120, 300]
🍽️ Real-World Analogy

A for loop is a waiter going table to table. The if is the waiter's rule: "only refill glasses that are less than half full." A list comprehension is the same waiter, but described in a single efficient sentence — "give every half-empty glass a refill" — instead of spelling out each step. Same work, cleaner instruction.

4. Functions: name a recipe, reuse it forever

A function packages a piece of logic behind a name so you can run it again and again. Good functions do one thing, have a clear name, take inputs (parameters), and return a result.

python — a clean function
def order_total(prices, tax_rate=0.18):
    """Return the after-tax total of a list of prices.

    prices:   list of numbers
    tax_rate: fraction of tax to add (default 18%)
    """
    subtotal = sum(prices)               # built-in sum() adds a list
    return subtotal * (1 + tax_rate)     # send the answer back

# Call it — the name documents intent better than inline math
print(round(order_total([120, 45, 300]), 2))   # -> 549.9
print(round(order_total([120, 45, 300], tax_rate=0.0), 2))  # no tax -> 465.0
⚠️ One job per function

If you can't describe a function in one short sentence without saying "and", it's doing too much — split it. load_data(), clean_data(), train_model() beats one giant do_everything(). Small, named, single-purpose functions are what make Week 13 onwards (where pipelines get long) stay readable.

5. Mini worked example: an order manager

Let's combine all four structures and a couple of functions into a tiny e-commerce program. Each order is a dict; all orders sit in a list; we use a set to find unique customers and dict lookups to total per customer.

python — order management
# Each order is a dict; the catalogue of orders is a list of dicts.
orders = [
    {"customer": "Asha",  "items": ["pen", "notebook"], "total": 165},
    {"customer": "Ravi",  "items": ["mouse"],            "total": 800},
    {"customer": "Asha",  "items": ["eraser"],           "total":  20},
]

def unique_customers(orders):
    """Return the set of distinct customer names (no duplicates)."""
    return {o["customer"] for o in orders}   # set comprehension

def spend_by_customer(orders):
    """Return a dict: customer name -> their total spend."""
    totals = {}
    for o in orders:
        name = o["customer"]
        # .get(name, 0) reads the running total, defaulting to 0 first time
        totals[name] = totals.get(name, 0) + o["total"]
    return totals

print(unique_customers(orders))   # -> {'Asha', 'Ravi'}
print(spend_by_customer(orders))  # -> {'Asha': 185, 'Ravi': 800}

# Find the top spender using max() with a key function
totals = spend_by_customer(orders)
top = max(totals, key=totals.get)
print(f"Top spender: {top} ({totals[top]})")   # -> Top spender: Ravi (800)

Notice how each structure earns its place: the list holds an ordered log of orders, each dict gives readable named fields, the set dedupes customers for free, and a second dict acts as a running tally. This "list of dicts" pattern is exactly how a query result from Week 5 arrives in Python.

✅ Check Yourself

You need a collection of coordinates that must never change after creation. Which type fits best?
Tuples are immutable — once created, their contents are frozen. That makes them perfect for fixed groups like (lat, long) where accidental modification would be a bug.
What does {p * 2 for p in [1, 2, 2, 3]} evaluate to?
The { } with no key:value pairs makes a set comprehension. It doubles each value (2, 4, 4, 6) then removes duplicates, leaving {2, 4, 6}.
In totals.get(name, 0), what is the role of the 0?
dict.get(key, default) returns the value if the key exists, otherwise the default. Here 0 lets the running tally start cleanly the first time a customer is seen — no KeyError.
