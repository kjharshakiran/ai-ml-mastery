Dimensionality Reduction I: Normalisation & Data Reduction

⏱️ 45 min🎯 Put every feature on the same footing📦 Week 19

By the end of this lesson you'll be able to…

  • Explain why features on wildly different scales break distance-based models.
  • Apply min–max normalisation to squeeze any feature into the range [0, 1].
  • Apply z-score standardisation and connect it back to the mean & standard deviation from Week 4.
  • Choose the right scaler and avoid the classic data-leakage trap.
  • Implement both by hand in NumPy and with scikit-learn's MinMaxScaler / StandardScaler.
The Big Question
If one feature is measured in dollars (0–100,000) and another in years (0–80), which one secretly dominates your model — and how do we give them a fair fight?

1. Data transformation: shaping data before it learns

So far we've fed models raw columns and hoped for the best. But real datasets are messy: one column counts website visits (0 to millions), another holds a customer's age (0 to 100), a third is a rating from 1 to 5. Data transformation is the family of steps that reshape these raw numbers into a form a model can learn from cleanly — and the most important member of that family is feature scaling.

Transformation is not "cheating" or "changing the data." It's translation. The relationships between data points stay intact; we just re-express every feature in a common currency so no single one shouts over the others.

🧒 Explain Like I'm 10

Imagine a race where one runner's distance is measured in millimetres and another's in kilometres. Even if they run equally hard, the millimetre numbers look gigantic next to the kilometre numbers. To judge fairly, you first convert everyone to the same unit. Normalisation is exactly that: putting every feature in the same unit so the model judges them fairly.

2. Why different scales hurt distance-based models

Remember the norm and distance from Week 2? A model like k-Nearest Neighbours (Week 15) decides "are these two points similar?" by computing the Euclidean distance between their feature vectors:

\[ d(\mathbf{a},\mathbf{b}) = \sqrt{\sum_i (a_i - b_i)^2} \]

Suppose person A is [salary=50000, age=30] and person B is [salary=50100, age=55]. The salary differs by 100 and the age by 25. But inside that square root, the salary term contributes \(100^2 = 10000\) while the age term contributes only \(25^2 = 625\). The salary completely drowns out the age — purely because its numbers happen to be bigger, not because it's more important. The distance is essentially "salary distance," and age stops mattering.

This isn't only a k-NN problem. Any algorithm that uses distances, dot products, or gradient steps in feature space is affected: SVMs (Week 18, whose margins live in distance-space), PCA (next week, which chases directions of maximum variance — and big-scale features fake big variance), and neural networks (Week 26, whose gradient descent converges far faster when inputs are scaled). Tree-based models (Week 21) are the notable exception — they split one feature at a time, so scale doesn't matter to them.

⚠️ Common Pitfall

"Bigger numbers" is not the same as "more important." A model can't tell the difference between a feature that matters and a feature that merely has large units. Scaling removes that confusion so the model can discover real importance from the data.

3. Min–max normalisation: squeeze into [0, 1]

The simplest fix rescales each feature so its smallest value becomes 0 and its largest becomes 1, with everything else spread linearly in between:

\[ x' = \frac{x - x_{\min}}{x_{\max} - x_{\min}} \]

Subtract the minimum (shifts the smallest value to 0), then divide by the range (shrinks the largest value to 1). Want a different range, say \([a,b]\)? Just stretch: \(x'' = a + x'(b-a)\).

Min–max is intuitive and preserves the exact shape of the distribution — it only slides and stretches. Its weakness: it's sensitive to outliers. One wildly large value sets \(x_{\max}\) and crushes every other point into a tiny sliver near 0.

📏 Real-World Analogy

Min–max is like grading an exam "on a curve to 0–100": the lowest score becomes 0%, the highest becomes 100%, everyone else lands proportionally between. But if one genius scores 10× everyone else, the whole class gets squashed near the bottom — that's the outlier sensitivity.

4. Z-score standardisation: centre and scale by spread

The other workhorse uses the mean \(\mu\) and standard deviation \(\sigma\) you met in Week 4. For each feature:

\[ z = \frac{x - \mu}{\sigma}, \qquad \mu = \frac{1}{n}\sum_i x_i, \qquad \sigma = \sqrt{\frac{1}{n}\sum_i (x_i - \mu)^2} \]

Subtract the mean (now the feature is centred at 0) and divide by the standard deviation (now its spread is exactly 1). The result, the z-score, literally answers: "how many standard deviations above or below average is this value?" A \(z=+2\) means "two standard deviations above the mean" — a rare, large value. A \(z=0\) means "exactly average."

Unlike min–max, z-scores aren't bounded to [0, 1] — they can be any real number. But they're far more robust to outliers, because \(\sigma\) summarises typical spread rather than depending on a single extreme. When a feature looks roughly bell-shaped (Gaussian, Week 4), standardisation is usually the right default — and it's what PCA expects next week.

🔑 The one thing to remember

Min–max answers "where does this value sit between the smallest and largest?" (bounded, outlier-sensitive). Z-score answers "how many standard deviations from average is this?" (unbounded, outlier-robust, ties directly to Week 4's \(\mu\) and \(\sigma\)).

numpy — both scalers by hand
import numpy as np

# Two features on very different scales: salary and age
X = np.array([[50000., 30.],
              [60000., 45.],
              [80000., 22.],
              [52000., 38.]])

# --- Min-max normalisation: (x - min) / (max - min), column by column ---
x_min = X.min(axis=0)          # smallest value in each column
x_max = X.max(axis=0)          # largest value in each column
X_minmax = (X - x_min) / (x_max - x_min)
print(X_minmax.round(2))       # every column now lives in [0, 1]

# --- Z-score standardisation: (x - mean) / std (the Week 4 formula) ---
mu  = X.mean(axis=0)           # per-feature mean  (Week 4)
sig = X.std(axis=0)            # per-feature standard deviation (Week 4)
X_zscore = (X - mu) / sig
print(X_zscore.round(2))       # each column now has mean 0, std 1
print(X_zscore.mean(axis=0).round(6))  # -> [0. 0.]  (centred)
print(X_zscore.std(axis=0).round(6))   # -> [1. 1.]  (unit spread)

5. The same thing with scikit-learn (and the leakage trap)

You'll rarely hand-roll scalers in practice — scikit-learn gives you MinMaxScaler and StandardScaler with a fit/transform API that integrates with pipelines. The critical rule: fit the scaler on training data only, then apply the same learned \(\mu,\sigma\) (or min/max) to the test data. Fitting on the whole dataset leaks information about the test set into training and inflates your scores.

scikit-learn — StandardScaler & MinMaxScaler
import numpy as np
from sklearn.preprocessing import StandardScaler, MinMaxScaler
from sklearn.model_selection import train_test_split

X = np.array([[50000., 30.], [60000., 45.], [80000., 22.],
              [52000., 38.], [70000., 50.], [48000., 27.]])

# Always split BEFORE scaling to avoid data leakage
X_train, X_test = train_test_split(X, test_size=0.33, random_state=0)

scaler = StandardScaler()          # z-score: subtract mean, divide by std
scaler.fit(X_train)                # learn mu and sigma from TRAIN ONLY
X_train_z = scaler.transform(X_train)
X_test_z  = scaler.transform(X_test)   # reuse the SAME mu, sigma on test
print("learned means :", scaler.mean_.round(1))
print("learned stds  :", scaler.scale_.round(1))

mm = MinMaxScaler()                # min-max: rescale each column to [0, 1]
X_train_mm = mm.fit_transform(X_train)   # fit + transform in one call
print(X_train_mm.round(2))

6. Data reduction: the bigger picture

Scaling is one half of preparing data; data reduction is the other. Real datasets can have hundreds or thousands of features, and more features is not always better — it brings the curse of dimensionality (data gets sparse, distances become meaningless, models overfit). Data reduction shrinks the dataset while keeping its signal. Three flavours:

  • Dimensionality reduction — fewer features, by combining correlated ones into new compact axes. This is exactly what PCA does next week.
  • Feature selection — keep the most informative columns, drop the rest.
  • Numerosity / sampling — fewer rows, by sampling or aggregating.

Why bother? Fewer dimensions mean faster training, less overfitting, lower memory, and — crucially — the ability to plot high-dimensional data in 2D so humans can see structure. But every reduction technique relies on features being on comparable scales first. That's why normalisation comes before reduction, and why this lesson comes right before PCA.

✅ Check Yourself

Why does a feature measured in the tens of thousands dominate Euclidean distance over a feature measured in tens?
Distance squares each feature's difference and sums them. A difference of 100 contributes 10,000; a difference of 25 contributes 625. The big-scale feature dominates purely because of units — which is exactly what scaling fixes.
A z-score of +2 for a data point means:
Z-score = (x − μ) / σ, so +2 literally means "two standard deviations above the mean" — a fairly rare, large value. This ties straight back to the μ and σ from Week 4.
Why must you fit a scaler on the training set only, not the whole dataset?
Fitting on all the data lets the test set influence the learned μ/σ (or min/max), so the model has secretly "seen" the test distribution. Fit on train, then transform test with those same parameters.
