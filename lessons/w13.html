Regression I: Linear & Multiple Linear Regression

⏱️ 55 min🎯 The simplest learning machine📦 Week 13

By the end of this lesson you'll be able to…

  • Frame numeric prediction as fitting a line \(y = wx + b\).
  • Define the least-squares loss and explain why we square the errors.
  • Solve for the best line in one shot with the normal equation.
  • Generalise to many features with multiple linear regression in vector form (a Week-2 dot product!).
  • Fit a regression in NumPy and scikit-learn and read off the coefficients.
The Big Question
Given a scatter of dots — house sizes vs prices — there are infinitely many lines you could draw through them. Which line is best, and can we compute it exactly instead of eyeballing it?

1. Numeric prediction: drawing the right line

Last lesson we placed regression on the map: supervised learning where the label is a number. Now we build the simplest possible regressor. Suppose each house has one feature — its size \(x\) in square metres — and a known price \(y\). Plot the data and you get a scatter of dots that roughly trends upward. Linear regression assumes the relationship is a straight line:

\[ \hat{y} = w x + b \]

Here \(w\) is the slope (how many dollars per extra square metre) and \(b\) is the intercept (the predicted price of a zero-size house — a useful baseline, even if not physically meaningful). The hat on \(\hat{y}\) means "our prediction," to distinguish it from the true \(y\). Learning = finding the \(w\) and \(b\) that make the line hug the dots.

🧒 Explain Like I'm 10

Imagine dots scattered on graph paper and a stretchy ruler. You slide and tilt the ruler until it sits right in the middle of the cloud of dots — not too high, not too low. The ruler is your prediction line: point at any spot along it and it tells you the price for that house size. Linear regression is just the maths for placing the ruler perfectly.

2. What makes a line "best"? The least-squares loss

For each data point, the line makes an error: the residual \(r_i = y_i - \hat{y}_i\), the vertical gap between the real dot and the line. A good line makes these gaps small overall. We score a line with the sum (or mean) of squared residuals:

\[ J(w, b) = \frac{1}{n}\sum_{i=1}^{n}\bigl(y_i - (w x_i + b)\bigr)^2 \]

Why square the errors rather than just add them? Three reasons: squaring makes every error positive (so overshoots and undershoots can't cancel), it punishes big misses far more than small ones (a residual of 4 costs 16, not 4), and — the deep reason — it makes \(J\) a smooth bowl-shaped function with a single lowest point we can find exactly.

3. Solving it exactly: the normal equation

Because \(J\) is a smooth bowl, its minimum is where the slope is zero. We could nudge \(w\) and \(b\) downhill step by step — that's gradient descent (Weeks 3 and 26), the universal method that scales to giant models. But for linear regression there's a shortcut: set the derivatives to zero and solve in one move. Stack the data into a matrix \(X\) (one row per example, with a column of 1s to absorb the intercept) and a vector \(\mathbf{y}\). The best parameter vector \(\mathbf{w}\) satisfies the normal equation:

\[ \mathbf{w}^\star = (X^\top X)^{-1} X^\top \mathbf{y} \]

That's it — a closed-form formula, no iteration, that hands you the optimal line directly. Under the hood it's the same least-squares projection that NumPy's lstsq performs. (When \(X^\top X\) is huge or ill-conditioned we prefer gradient descent, which is the bridge to everything in Part 5.)

🔑 The one thing to remember

Linear regression = pick the line that minimises the sum of squared vertical errors. There's a one-shot formula for the answer (the normal equation), and there's an iterative way (gradient descent) that generalises to every model you'll meet later. Same goal, two routes.

4. Multiple linear regression: many features at once

Houses aren't described by size alone — there's also the number of bedrooms, the age, the distance to the city centre. Each example becomes a feature vector \(\mathbf{x} = [x_1, x_2, \dots, x_d]\), and the prediction becomes a weighted sum of all features plus a bias:

\[ \hat{y} = w_1 x_1 + w_2 x_2 + \dots + w_d x_d + b = \mathbf{w}\cdot\mathbf{x} + b \]

Look closely: \(\mathbf{w}\cdot\mathbf{x}\) is exactly the dot product from Week 2. Each weight \(w_j\) says how much feature \(j\) pushes the prediction up or down. Geometrically, instead of a line in 2D we're fitting a flat hyperplane through points in \((d{+}1)\)-dimensional space — but the recipe is identical: minimise squared error, and the very same normal equation \(\mathbf{w}^\star = (X^\top X)^{-1}X^\top\mathbf{y}\) solves it, now with \(X\) holding all \(d\) feature columns.

🍰 Real-World Analogy

Think of a price as a recipe. Each ingredient (feature) contributes a fixed amount per unit: +\$1,500 per square metre, +\$10,000 per bedroom, −\$800 per year of age. The dot product \(\mathbf{w}\cdot\mathbf{x}\) just totals up everyone's contribution. Training is figuring out the per-ingredient prices \(\mathbf{w}\) from past sales.

5. Doing it in code — two ways

Let's fit the same data twice: first by literally coding the normal equation in NumPy, then with scikit-learn's LinearRegression. They should agree to the decimal.

numpy (normal equation) vs sklearn
import numpy as np
from sklearn.linear_model import LinearRegression

# Toy data: 2 features (size, bedrooms) -> price.  True rule: price = 3*size + 50*beds + 20
rng = np.random.default_rng(0)
size = rng.uniform(50, 200, size=40)
beds = rng.integers(1, 5, size=40)
X = np.column_stack([size, beds])                 # shape (40, 2): one row per house
y = 3*size + 50*beds + 20 + rng.normal(0, 10, 40) # add a little noise

# ---- Method A: the normal equation, by hand ----
# Add a column of 1s so the intercept b is just another weight
Xb = np.column_stack([np.ones(len(X)), X])        # shape (40, 3): [1, size, beds]
w = np.linalg.inv(Xb.T @ Xb) @ Xb.T @ y           # w* = (X^T X)^-1 X^T y
print("normal eq  [b, w_size, w_beds] =", np.round(w, 2))   # ~[20, 3, 50]

# ---- Method B: scikit-learn ----
model = LinearRegression().fit(X, y)              # solves the same least-squares problem
print("sklearn    intercept b =", round(model.intercept_, 2))   # ~20
print("sklearn    coefs [w_size, w_beds] =", np.round(model.coef_, 2))  # ~[3, 50]

# Predict the price of a new 120 m^2, 3-bedroom house
print("prediction =", round(model.predict([[120, 3]])[0], 2))

The recovered coefficients (\(\approx 3\) per square metre, \(\approx 50\) per bedroom, intercept \(\approx 20\)) match the rule that generated the data — the model learned the recipe from examples. And the hand-coded normal equation and sklearn produce the same numbers, because they're solving the identical least-squares problem.

⚠️ Watch out

Inverting \(X^\top X\) directly is fine for a few features but numerically fragile when features are large or highly correlated. In practice prefer np.linalg.lstsq or scikit-learn (which use stable factorisations), and standardise your features so no single column dominates — a habit we formalise in Week 19.

🔗 Connect the Dots

Linear regression is the simplest learning machine, and it stitches together earlier weeks: the prediction \(\mathbf{w}\cdot\mathbf{x}+b\) is the dot product of Week 2, and minimising the squared-error loss is the optimisation of Week 3 (with gradient descent returning in force in Week 26). Next lesson, Week 14, we let the model bend into curves and meet its greatest enemy — overfitting — plus the cure, regularisation. And its classification cousin, logistic regression (Week 25), reuses this exact \(\mathbf{w}\cdot\mathbf{x}+b\) core but squashes the output into a probability.

✅ Check Yourself

In \(\hat{y} = wx + b\), what does the slope \(w\) represent?
The slope is the rate of change: add one unit of \(x\) and the prediction moves by \(w\). The intercept \(b\) is the value at \(x=0\).
Why does least-squares regression square the residuals instead of just summing them?
Squaring makes errors positive (no cancelling), heavily penalises large errors, and produces a convex loss with a single, exactly-solvable minimum — the normal equation.
In multiple linear regression, the prediction \(\mathbf{w}\cdot\mathbf{x}+b\) is built from which Week-2 operation?
\(\mathbf{w}\cdot\mathbf{x}=\sum_j w_j x_j\) is exactly the dot product from Week 2 — each weight scales its feature and the results are summed. This same core reappears in logistic regression and every neural-network neuron.
