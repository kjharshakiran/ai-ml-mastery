Decision Trees & CART

⏱️ 50 min🎯 Learning a flowchart from data📦 Week 21

By the end of this lesson you'll be able to…

  • Read a decision tree as a flowchart of yes/no questions.
  • Describe the CART algorithm that grows one from data.
  • Measure node "messiness" with Gini impurity and entropy / information gain.
  • Understand greedy splitting, stopping criteria, and why pruning fights overfitting.
  • Train a DecisionTreeClassifier and read its feature importances.
The Big Question
How can a model learn the same kind of common-sense rules a doctor uses — "if fever AND cough, then…" — directly from data, with no equations to tune?

1. A decision tree is a learned flowchart

Every model so far drew a boundary with geometry — lines, margins, distances. A decision tree does something refreshingly human instead: it asks a sequence of yes/no questions. "Is the petal longer than 2.5 cm? If yes, go left; if no, go right. Then ask the next question…" Each question splits the data; you follow the branches until you reach a leaf, which gives the prediction.

The whole model is just a tree of questions. No weights, no gradients — and best of all, you can read it. That interpretability is why trees are beloved in medicine, finance, and anywhere a human must trust (or audit) the decision.

🧒 Explain Like I'm 10

It's the game 20 Questions. "Is it an animal? Does it have fur? Is it bigger than a cat?" Each yes/no answer narrows things down until you're sure. A decision tree plays 20 Questions with data — and it figures out, by itself, which questions to ask and in what order.

2. CART: how the tree is grown

CART (Classification And Regression Trees) is the standard algorithm — it's what scikit-learn uses. It builds binary trees greedily, top-down:

  1. Start with all the data at the root.
  2. Try every feature and every possible threshold; pick the split that makes the two resulting groups as pure as possible (one class dominates each side).
  3. Recurse on each child node.
  4. Stop when a node is pure, too small, or a depth limit is hit; that node becomes a leaf.

"Greedy" means it grabs the best split right now without planning ahead — fast, and good enough in practice. The same machinery handles regression too (leaves predict an average instead of a class), but we'll focus on classification.

3. Measuring impurity: Gini and entropy

To "pick the best split" we need a number for how mixed-up a node is. A node with only one class is perfectly pure (impurity 0); a 50/50 mix is maximally impure. Two standard measures, where \(p_k\) is the fraction of class \(k\) in the node:

Gini impurity — the chance you'd mislabel a random point if you guessed by the node's class proportions:

\[ \text{Gini} = 1 - \sum_{k} p_k^{2} \]

Entropy — the "surprise" or disorder of the node, borrowed from information theory:

\[ H = -\sum_{k} p_k \log_2 p_k \]

Both are 0 for a pure node and peak for an even mix (for two classes, Gini peaks at 0.5, entropy at 1 bit). CART then scores a split by how much it reduces impurity. With entropy, that reduction has a famous name — information gain:

\[ \text{IG} = H_{\text{parent}} - \sum_{\text{child}} \frac{n_{\text{child}}}{n_{\text{parent}}}\,H_{\text{child}} \]

In words: parent's disorder minus the weighted average disorder of the children. The split with the highest information gain (or biggest Gini drop) wins.

Information gain on one split, by hand

The formula is abstract until you watch disorder actually drop, so let's score a single split end-to-end. The parent node holds 10 samples, evenly mixed: 5 positive, 5 negative.

Parent55
Left child41
Right child14

Step 1 — parent entropy. A 50/50 mix is maximally disordered, \(p=0.5\) for each class:

\[ H_{\text{parent}} = -\bigl(0.5\log_2 0.5 + 0.5\log_2 0.5\bigr) = 1.0 \text{ bit} \]

Step 2 — child entropies. Each child is an 80/20 mix, so \(p=0.8\) and \(p=0.2\):

\[ H_{\text{left}} = H_{\text{right}} = -\bigl(0.8\log_2 0.8 + 0.2\log_2 0.2\bigr) \approx 0.722 \text{ bit} \]

Step 3 — weighted child entropy and gain. Each child holds half the samples, so the weighted average is \(0.5(0.722)+0.5(0.722)=0.722\). The information gain is the drop:

\[ \text{IG} = 1.0 - 0.722 = 0.278 \text{ bit} \]

This split earns \(0.278\) bit of gain. Compare a useless split whose children are still 50/50: their weighted entropy is \(1.0\), so \(\text{IG}=0\) — no tidying at all. (Gini agrees on the ranking: parent Gini \(=0.5\), each child \(1-(0.8^2+0.2^2)=0.32\), a drop of \(0.18\); Gini and entropy pick the same winning splits.)

🔑 Gain is the feature's credit

CART tries every feature and threshold and keeps the split with the largest IG — here \(0.278\) bit. That same number is also what gets tallied into the feature's importance: a feature that repeatedly delivers big gains near the top of the tree is exactly the one the model leans on most.

🗂️ Real-World Analogy

Sorting a drawer of mixed socks. A good first split — "darks vs lights" — instantly makes each pile much more uniform. A useless split — "left sock vs right sock" — leaves both piles just as mixed. Information gain is the math for "how much tidier did this split make things?" The tree always picks the tidiest split available.

🔑 The one thing to remember

A decision tree is built by greedily choosing splits that most reduce impurity. Gini and entropy are two ways to measure that impurity; in practice they give very similar trees, and Gini is slightly faster (no logarithm).

numpy — impurity by hand
import numpy as np

def gini(p):
    p = np.asarray(p)
    return 1 - np.sum(p**2)          # 1 - sum of squared class proportions

def entropy(p):
    p = np.asarray(p)
    p = p[p > 0]                     # avoid log(0)
    return -np.sum(p * np.log2(p))   # information-theoretic disorder

pure  = [1.0, 0.0]                   # all one class
mixed = [0.5, 0.5]                   # perfectly split
print("Gini pure / mixed:   ", gini(pure),    gini(mixed))     # 0.0  0.5
print("Entropy pure / mixed:", entropy(pure), entropy(mixed))  # 0.0  1.0

4. Query selection, stopping & the overfitting trap

If you let CART keep splitting, it will eventually carve out a leaf for every single training point — 100% training accuracy, and a tree that has memorised noise. That's overfitting, the same villain from Week 14. A fully-grown tree is the poster child for high variance: change a few training points and the tree reshapes wildly.

Two defences:

  • Pre-pruning (early stopping) — cap the tree before it grows wild: limit max_depth, require a minimum number of samples to split (min_samples_split) or per leaf (min_samples_leaf).
  • Post-pruning — grow a big tree, then snip back branches that don't improve performance on held-out data (e.g. cost-complexity pruning, ccp_alpha).

A pruned tree is shallower, more general, and usually more accurate on new data — trading a little training accuracy for a lot of robustness.

⚠️ Common Pitfall

A single deep tree that scores 100% on training data is almost always overfit, not brilliant. Always limit depth or prune, and judge the tree on a validation set — never on the data it was grown from.

scikit-learn — train a tree & read importances
from sklearn.datasets import load_iris
from sklearn.tree import DecisionTreeClassifier, export_text
from sklearn.model_selection import train_test_split

X, y = load_iris(return_X_y=True)
names = load_iris().feature_names
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=0)

# max_depth=3 pre-prunes the tree so it can't memorise the training set
clf = DecisionTreeClassifier(criterion="gini", max_depth=3, random_state=0)
clf.fit(Xtr, ytr)
print("test accuracy:", round(clf.score(Xte, yte), 3))     # ~0.98

# Feature importance = total impurity reduction each feature provided
for name, imp in zip(names, clf.feature_importances_):
    print(f"{name:<20} {imp:.3f}")          # petal features dominate

print(export_text(clf, feature_names=names))   # the learned if/else rules

Feature importance falls out for free: a feature that produced big impurity reductions near the top of the tree is clearly important. It's one of the most useful by-products trees give you — a ranked list of which features actually drove the decisions.

🔗 Connect the Dots

Trees revive the overfitting/variance theme from Week 14, now solved by pruning instead of regularisation. They also don't care about feature scale, so unlike Week 19's distance models, no normalisation is needed. Most importantly, a single tree is the building block of ensembles: next week (Week 22) we combine hundreds of trees into random forests and boosting — turning this week's high-variance learner into some of the strongest classical models there are.

✅ Check Yourself

When CART chooses a split, what is it trying to maximise?
CART greedily picks the feature/threshold whose split most reduces impurity — measured as information gain (entropy) or the drop in Gini. Purer children mean a more confident prediction.
A node contains only points of a single class. What is its Gini impurity?
Gini = 1 − Σpₖ². With one class, p = 1, so Gini = 1 − 1² = 0. A pure node has zero impurity and becomes a leaf.
Your decision tree gets 100% accuracy on training data but only 70% on test data. The likely cause and fix?
A perfect training score with a big test drop is classic overfitting (high variance). Pre-pruning (max_depth, min_samples_leaf) or post-pruning shrinks the tree so it generalises — the Week 14 lesson, applied to trees.
