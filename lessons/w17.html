SVM I: Discriminant Functions & the Perceptron

  • See how a Bayes classifier secretly produces a discriminant.

The Big Question
Last week we modelled each class with a whole probability distribution just to decide which side a point falls on. That's a lot of work for one line. What if we skipped the modelling and learned the boundary itself directly — and could a machine learn that boundary just by fixing its own mistakes?

1. Classification via discriminant functions

A discriminant function \(g(\mathbf{x})\) is any function whose sign tells you the class. For two classes, the rule is brutally simple: predict class +1 if \(g(\mathbf{x})>0\), and class −1 if \(g(\mathbf{x})<0\). The set of points where \(g(\mathbf{x})=0\) is the decision boundary. The most useful discriminant is linear — a straight line (or, in higher dimensions, a flat hyperplane):

\[ g(\mathbf{x}) = \mathbf{w}\cdot\mathbf{x} + b, \qquad \text{boundary: } \mathbf{w}\cdot\mathbf{x} + b = 0 \]

That \(\mathbf{w}\cdot\mathbf{x}\) is the dot product from Week 2. The vector \(\mathbf{w}\) is perpendicular to the boundary — it points "uphill" toward the positive class — and \(b\) shifts the line away from the origin.

🧒 Explain Like I'm 10

Draw a line on the playground. Footballers on one side, chess players on the other. A new kid shows up — you don't need to study anyone's whole personality, you just check which side of the line they're standing on. The line is the classifier. Learning means nudging the line until it splits the two groups.

2. The discriminant hiding inside a Bayes classifier

Last week's Bayes classifier was already a discriminant in disguise. Define \(g(\mathbf{x}) = \log P(C_1\mid\mathbf{x}) - \log P(C_2\mid\mathbf{x})\). Its sign picks the winning class, so it is a discriminant function. Remarkably, if both classes are Gaussians sharing the same covariance, all the curvy exponentials cancel and \(g\) collapses to a straight line — a linear discriminant. So generative and discriminative methods can land on the very same boundary by completely different routes.

3. Generative methods: a quick summary

Methods like Bayes, Naïve Bayes, and GMM are generative (sometimes called non-discriminative): they learn \(P(\mathbf{x}\mid C)\) — a full model of how each class generates data — and only then derive the boundary by inversion. The upside: they cope with missing data, give calibrated probabilities, work well when training data is scarce (because the modelling assumptions do some of the heavy lifting), and can even synthesise brand-new samples. The downside: modelling an entire distribution is a lot of work when all you wanted was a single dividing line, and if your distributional assumptions are wrong, the boundary inherits those errors. When you have plenty of data and only care about the decision, learning the boundary directly is usually both simpler and more accurate.

4. Discriminative methods: learn the boundary directly

Discriminative methods skip the distributions and fit \(\mathbf{w}\) and \(b\) so the boundary separates the classes. They don't waste effort describing what spam looks like; they only learn what tells spam apart from ham. The perceptron, logistic regression, and SVMs are all discriminative.

🍊 Real-World Analogy

Sorting oranges from grapefruit: a generative grader studies each fruit in detail — builds a full mental portrait of a typical orange and a typical grapefruit — then judges. A discriminative grader just notices "grapefruit are bigger" and sets a size threshold. Less understanding, but it sorts the conveyor belt faster and just as well.

5. The perceptron: a machine that learns from its mistakes

The perceptron (Rosenblatt, 1958) is the grandparent of every neural network. It is a linear discriminant that trains itself with one gorgeously simple rule: only adjust the weights when you get an example wrong. Its prediction is the sign of the dot product:

\[ \hat{y} = \operatorname{sign}(\mathbf{w}\cdot\mathbf{x} + b) \]

For each training point, if the prediction is correct, do nothing. If it's wrong, nudge the weights toward the right answer:

\[ \mathbf{w} \leftarrow \mathbf{w} + \eta\,(y - \hat{y})\,\mathbf{x}, \qquad b \leftarrow b + \eta\,(y - \hat{y}) \]

Here \(\eta\) is the learning rate and \(y\in\{-1,+1\}\) is the true label. The term \((y-\hat{y})\) is zero on correct points and \(\pm 2\) on mistakes, so the weights only move when needed — rotating the boundary to fix the error. The perceptron convergence theorem promises that if the data is linearly separable, this loop is guaranteed to find a separating line in a finite number of steps.

numpy — a perceptron from scratch
import numpy as np

# Tiny linearly separable 2D dataset, labels in {-1, +1}
X = np.array([[2, 1], [3, 2], [1, 1],     # class +1 cluster
              [-2, -1], [-3, -2], [-1, -2]])  # class -1 cluster
y = np.array([1, 1, 1, -1, -1, -1])

w = np.zeros(2)        # weight vector (the boundary's normal)
b = 0.0                # bias / offset
eta = 0.1              # learning rate

for epoch in range(10):                 # passes over the data
    errors = 0
    for xi, yi in zip(X, y):
        y_hat = np.sign(np.dot(w, xi) + b)   # predict: sign of w·x + b
        if y_hat != yi:                       # only update on a MISTAKE
            w += eta * (yi - y_hat) * xi
            b += eta * (yi - y_hat)
            errors += 1
    if errors == 0:                           # separable -> converges
        print(f"converged after epoch {epoch}")
        break

print("weights:", w, " bias:", round(b, 2))
# Check it separates the data: every w·x + b should match the label's sign
print("all correct:", np.all(np.sign(X @ w + b) == y))   # -> True
🔑 The one thing to remember

A perceptron computes a weighted sum of inputs, applies a threshold, and corrects its weights whenever it errs. Swap that hard threshold for a smooth activation function and you have exactly one neuron of a neural network. Everything in deep learning grows from this seed.

⚠️ Pitfall

If the data is not linearly separable, the basic perceptron never settles — it loops forever, flip-flopping the boundary. This famous limitation (no single line can solve XOR) stalled the field for years, until multi-layer networks and SVM margins fixed it. That's exactly where next week and Week 24 pick up.

🔗 Connect the Dots

The boundary \(\mathbf{w}\cdot\mathbf{x}+b=0\) is built on the dot product from Week 2, and "which class wins" extends the generative Bayes view of Week 16. The perceptron is literally one neuron — it is the direct ancestor of the neural networks in Week 24 and the backpropagation of Week 25. ✅ Check Yourself

A discriminant function g(x) classifies a point by…
The boundary is g(x) = 0; the sign on either side picks the class. For a linear discriminant, g(x) = w·x + b.
When does the perceptron update its weights?
The factor (y − ŷ) is zero for correct predictions, so the rule w ← w + η(y − ŷ)x leaves the weights untouched unless there's a mistake to fix.
What's the key difference between generative and discriminative classifiers?
Bayes/Naïve Bayes/GMM (generative) learn P(x | C); the perceptron and SVMs (discriminative) skip that and fit the separating boundary itself.
