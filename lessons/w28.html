CNNs I: Convolution & Pooling

The Big Question
A single 224×224 colour photo is ~150,000 numbers. If we shove that into a dense network, the first layer alone needs billions of weights — and it still wouldn't know that a cat shifted two pixels left is the same cat. How do we look at images intelligently?

28.1 Why dense networks drown in images

Back in Week 10 we learned the key fact: an image is just a tensor of pixel numbers — a grid of brightness values, with three channels (R, G, B) for colour. That framing is exactly what we build on now. The trouble is the sheer size. A modest \(224\times224\) RGB image is \(224\times224\times3 = 150{,}528\) numbers. If you flatten that into a vector and feed it to a fully-connected (dense) layer of just 1000 neurons — the kind of MLFFNN from Weeks 24–27 — that one layer needs \(150{,}528\times1000 \approx 150\) million weights.

Worse, flattening throws away spatial structure. Pixel (10,10) and pixel (10,11) are neighbours — they almost certainly belong to the same edge or texture — but to a dense layer they're just entries #1230 and #1231 in a long list, no more related than any other pair. The network has to re-learn "these pixels are near each other" from scratch, for every position, using a mountain of parameters. There is a smarter way, and it comes from one beautifully simple idea.

🧒 Explain Like I'm 10

Imagine looking for Waldo in a giant picture. You don't stare at all million dots at once — that's overwhelming. Instead you take a little cardboard window with a tiny picture of Waldo's hat, and slide it across the page, asking "does the bit under my window look like a stripey hat?" everywhere you go. A CNN does exactly that: it slides tiny pattern-detectors across the image. Same little detector, reused everywhere. That's the whole trick.

28.2 Convolution: a tiny filter slides and listens

A convolutional filter (or kernel) is a small grid of weights — often just \(3\times3\). We slide it across the image, and at each position we lay it over the patch of pixels beneath it and compute a single number: multiply matching cells, add them all up. That "multiply-and-sum" is exactly the dot product you met in Week 2 — the operation that measures "how much do these two things look alike?" The filter is asking, at every location, "how strongly does this patch resemble my pattern?"

Stack all those answers back into a grid and you get a feature map: a new image that lights up wherever the filter's pattern appears. Formally, for an input \(I\) and a \(K\times K\) kernel \(W\), the value of the feature map at position \((i,j)\) is:

\[ S(i,j) \;=\; \sum_{m=0}^{K-1}\sum_{n=0}^{K-1} I(i+m,\; j+n)\,\cdot\,W(m,n) \;+\; b \]

That double sum is one dot product between the kernel and the patch it covers, plus a bias \(b\). A filter whose weights look like \(\begin{smallmatrix}-1&0&1\\-1&0&1\\-1&0&1\end{smallmatrix}\) responds strongly to a vertical edge (bright on the right, dark on the left) and ignores flat regions. The magic of deep learning: we don't hand-design these filters — backprop (Week 25) learns them.

Two knobs control the slide. Stride is how far the filter jumps each step (stride 1 = every pixel, stride 2 = every other → a smaller output). Padding adds a border of zeros so the output can keep the input's size and edge pixels aren't neglected. A \(K\times K\) filter on an \(N\times N\) input with no padding and stride 1 yields an \((N-K+1)\times(N-K+1)\) map — that's why our \(5\times5\) input above produced a \(3\times3\) map.

28.3 Pooling: shrink, summarise, toughen up

After convolution we usually pool: slide a small window (say \(2\times2\)) and replace each window with a single summary number. Max-pooling keeps the maximum — it asks "did this feature fire anywhere in this little neighbourhood?" Pooling does three good things: it shrinks the map (less computation downstream), it widens each later neuron's view of the image, and it grants a dose of translation tolerance — nudge the input a pixel and the max often doesn't change.

🔎 Real-World Analogy

Convolution is a swarm of identical rubber stamps, each printing "I found my pattern here!" wherever its shape appears. Max-pooling is a manager who walks by each \(2\times2\) block and only reports the loudest stamp: "Yes, something fired in this corner." The manager doesn't care about the exact pixel — just roughly where — which is precisely why a cat shifted two pixels still reads as a cat.

28.4 MLFFNN vs CNN: three superpowers

Why does this beat a dense network so badly? Three reasons, each a direct fix for a dense net's weakness:

  • Local connectivity. A neuron looks only at a tiny patch (its receptive field), not the whole image. Nearby pixels are wired together; distant ones aren't — matching how images actually work.
  • Weight sharing. The same \(3\times3\) filter is reused at every position. A \(3\times3\) filter on a colour image is just \(3\times3\times3+1 = 28\) parameters — versus 150 million for one dense layer. An edge is an edge whether it's top-left or bottom-right, so why learn it 50,000 times?
  • Translation invariance. Because the filter slides everywhere and pooling blurs exact position, a pattern is detected no matter where it sits. A dense net would have to learn "cat at top-left," "cat at centre," etc., separately.
🔑 The one thing to remember

A CNN is an MLFFNN with two constraints baked in: each neuron sees only a local patch, and neurons across the image share one set of weights. Those two constraints slash the parameter count by orders of magnitude and bake in the prior that "vision is local and position-tolerant." It learns faster, generalises better, and needs far less data.

28.5 Stacking it up: from edges to objects

One conv layer with many filters produces many feature maps (one per filter — edges, blobs, colour gradients). We pass each through a ReLU nonlinearity (from Week 24) to keep only positive activations, then pool. Then we do it again on those feature maps, and again. A repeating conv → ReLU → pool block is the heartbeat of a CNN.

The beautiful part is the hierarchy. Early layers, looking at raw pixels, learn simple edges and colours. Middle layers, looking at combinations of edges, learn corners, curves and textures. Deep layers learn parts — an eye, a wheel, a doorknob — and finally whole objects. After several blocks we flatten the small feature maps into a vector and feed it to an ordinary dense "head" (Weeks 24–27) with a softmax that outputs class probabilities: cat, dog, car.

This recipe defines the classic image classifiers. LeNet-5 (1998) used it to read handwritten digits. AlexNet (2012) scaled it up with ReLU, dropout and GPUs and shattered the ImageNet benchmark, igniting the deep-learning boom. VGG (2014) showed that simply stacking many small \(3\times3\) convolutions deep makes networks even stronger — a design idea we still use today.

numpy — a tiny 2D convolution + max-pool
import numpy as np

# A 6x6 grayscale "image" with a bright vertical stripe down the middle.
img = np.array([
    [0, 0, 9, 9, 0, 0],
    [0, 0, 9, 9, 0, 0],
    [0, 0, 9, 9, 0, 0],
    [0, 0, 9, 9, 0, 0],
    [0, 0, 9, 9, 0, 0],
    [0, 0, 9, 9, 0, 0],
], dtype=float)

# A 3x3 vertical-edge detector: positive on the right, negative on the left.
kernel = np.array([
    [-1, 0, 1],
    [-1, 0, 1],
    [-1, 0, 1],
], dtype=float)

def conv2d(x, w):
    """Valid 2D convolution (stride 1, no padding). Each output cell is one
    dot product between the kernel and the patch it covers."""
    kh, kw = w.shape
    out_h, out_w = x.shape[0] - kh + 1, x.shape[1] - kw + 1
    out = np.zeros((out_h, out_w))
    for i in range(out_h):
        for j in range(out_w):
            patch = x[i:i+kh, j:j+kw]   # the window under the filter
            out[i, j] = np.sum(patch * w)  # multiply-and-sum == dot product
    return out

def maxpool2d(x, size=2):
    """Non-overlapping max-pooling: keep the loudest value per size x size block."""
    out_h, out_w = x.shape[0] // size, x.shape[1] // size
    out = np.zeros((out_h, out_w))
    for i in range(out_h):
        for j in range(out_w):
            block = x[i*size:(i+1)*size, j*size:(j+1)*size]
            out[i, j] = block.max()
    return out

feat = conv2d(img, kernel)
print("feature map:\n", feat)
# The map is ~0 in flat regions and spikes at the stripe's edges:
# negative where dark->bright transitions, positive on the other side.

pooled = maxpool2d(np.abs(feat))   # |edges|, then summarise 2x2 blocks
print("pooled (|edge| strength):\n", pooled)
# Smaller grid, with the edge response preserved -> "an edge lives here."
🔗 Connect the Dots

Convolution is literally the dot product from Week 2 applied to pixel tensors from Week 10, slid across the image. The filters aren't designed — they're learned by backpropagation (Week 25), the same gradient machinery that trains every net in this part. ✅ Check Yourself

What single arithmetic operation does a convolution perform at each position?
Each output cell is the element-wise product of kernel and patch, summed to one number — exactly the dot product from Week 2. Slide it everywhere and you get a feature map.
Why does a CNN need far fewer parameters than a dense net for images?
A 3×3 filter is ~28 weights and is reused across the whole image. A dense layer needs a separate weight for every input pixel — millions of them. Sharing is the saving.
What does max-pooling mainly buy you?
Taking the max over a window downsamples the map and makes the response insensitive to exact position — a key source of translation tolerance.
