Transformers II: Positional Encoding & Pre-training

The Big Question
Attention lets every word look at every other word at once — but it does so without any sense of who came first. So how does a transformer know that "dog bites man" is a very different story from "man bites dog"? And once we fix that, how does it learn grammar, facts, and reasoning from raw text it has never been told the answers to?

33.1 Attention is order-blind — and positional encoding cures it

Last lesson ended with a warning that we now have to pay off. Self-attention computes, for every pair of tokens, a dot-product score and a weighted blend of values. Look closely at that machinery: there is nothing in it that depends on where a token sits in the sentence. If you shuffle the input words, the same set of Query/Key/Value vectors comes out — just reordered — and the attention output is reordered the same way. Mathematically, self-attention is permutation-equivariant: it treats the input as a bag of tokens, not a sequence.

For an RNN (Week 30) this was never a problem — it physically reads left to right, so order is baked into the wiring. But we threw the RNN away precisely to gain parallelism. We bought speed and paid for it with amnesia about position. We need to inject the missing information back in.

🧒 Explain Like I'm 10

Imagine you cut a sentence into word-cards and toss them on a table in a pile. Attention is great at noticing "this card and that card are related!" — but it has no idea which card came first, because they're all just lying there in a heap. So before we drop the cards in, we stamp a little number on each one: "I'm word #1," "I'm word #2." Now even in a messy pile, every card remembers its place in line. That stamp is the positional encoding.

The fix is simple and elegant: give each position its own vector, and add it to the token's embedding before the first attention layer. The word "dog" at position 1 and the word "dog" at position 5 now enter the network as different vectors, so attention can tell them apart. The combined input is just:

\[ \mathbf{x}_i = \mathbf{e}_{\text{token}_i} + \mathbf{p}_i \]

where \(\mathbf{e}\) is the word embedding from Week 31 and \(\mathbf{p}_i\) is the positional vector for slot \(i\). Both live in the same \(d\)-dimensional space, so addition is meaningful — the position vector nudges the word's meaning slightly in a direction that encodes "where I am."

Sinusoidal positional encoding — the clever original

How do we build \(\mathbf{p}_i\)? The original transformer used a fixed, hand-designed pattern of sines and cosines of different frequencies. For position \(pos\) and dimension index \(i\) (out of \(d\) total), the encoding is:

\[ PE_{(pos,\,2i)} = \sin\!\left(\frac{pos}{10000^{\,2i/d}}\right), \qquad PE_{(pos,\,2i+1)} = \cos\!\left(\frac{pos}{10000^{\,2i/d}}\right) \]

Read it as a set of "clock hands" spinning at different speeds. The first dimensions use a high frequency (a fast hand that ticks every few positions); later dimensions use very low frequencies (a slow hand that barely moves across the whole sentence). Together, the pattern of hand-positions forms a unique "binary-clock" fingerprint for every slot — much like how binary counting uses bits flipping at halved rates. Two nice properties fall out for free:

  • Every position gets a unique vector, yet nearby positions get similar vectors — so "distance in the sentence" maps to "distance in encoding space."
  • Because of trig identities, \(PE_{pos+k}\) is a fixed linear function of \(PE_{pos}\). The model can learn relative offsets ("the word three slots back") with a simple linear operation, and it extrapolates gracefully to sentence lengths never seen in training.

Two positional-encoding cells, by hand

Let's evaluate the formula for real to watch the fast and slow clock hands tick. Take \(d = 4\), so we have two sine/cosine pairs. For \(2i = 0\) the denominator is \(10000^{0} = 1\); for \(2i = 2\) it is \(10000^{2/4} = 100\). Plugging in positions 1 and 2:

positiondim 0 \(\sin(pos/1)\)dim 1 \(\cos(pos/1)\)dim 2 \(\sin(pos/100)\)dim 3 \(\cos(pos/100)\)
\(pos = 1\)0.8410.5400.0101.000
\(pos = 2\)0.909-0.4160.0201.000

Step 1 — the fast pair (left). Dim 0 uses \(\sin(pos)\) directly, so it leaps from \(\sin(1) = 0.841\) to \(\sin(2) = 0.909\), and dim 1 swings from \(\cos(1)=0.540\) to \(\cos(2)=-0.416\) — a big change for a single step.

Step 2 — the slow pair (right). Dim 2 is \(\sin(pos/100)\), so \(\sin(0.01)=0.010\) creeps to \(\sin(0.02)=0.020\), and dim 3 stays pinned at \(\cos \approx 1.000\). The right pair barely moves.

So \(\mathbf{p}_1 \approx [0.841,\, 0.540,\, 0.010,\, 1.000]\) and \(\mathbf{p}_2 \approx [0.909,\, -0.416,\, 0.020,\, 1.000]\) — literal fast and slow clock hands: the left pair races, the right pair crawls.

🔑 Different dimensions tick at different speeds

Each dimension oscillates at its own frequency — fast on the left, glacial on the right. The combination of all these hand-positions gives every slot a unique fingerprint the model can read and compare, so it can tell position 1 from position 2 from position 200.

🕰️ Real-World Analogy: a wall of clocks

Picture a bank of clocks, each running at a different speed — one ticks every second, one every minute, one every hour, one every day. Glance at all of them at once and the combination of hand-positions tells you exactly what moment it is, with no two moments looking alike. Sinusoidal encoding is that wall of clocks: fast sines pin down fine position, slow sines pin down coarse position, and together they stamp each word with a one-of-a-kind timestamp.

Learned positional embeddings — the modern default

Many modern models (including the GPT and BERT families) skip the hand-crafted sines and instead use a learned positional embedding: a lookup table with one trainable vector per position, optimised by gradient descent just like the word embeddings. It's simpler and lets the model discover whatever positional pattern is most useful — at the cost of not extrapolating past the maximum length it was trained on. Newer schemes (RoPE, ALiBi) inject position inside the attention scores rather than adding it at the input, but the core idea is identical: attention has no notion of order, so we must supply it.

🔑 The one thing to remember

Self-attention sees a bag of tokens. Positional encoding stamps each token with its place in line — a vector we add to the embedding — so the model can finally tell "dog bites man" from "man bites dog."

33.2 The cost of attention: why context is expensive

Attention's superpower is that every token can look at every other token. But "every-to-every" has a price. For a sequence of \(n\) tokens, the score matrix \(QK^\top\) has \(n \times n\) entries — one similarity for each ordered pair. Computing and storing it is \(O(n^2)\) in both time and memory.

That single fact explains a huge amount of LLM economics. Double the context length and you quadruple the attention cost. Going from a 2,000-token prompt to a 100,000-token prompt isn't 50× harder — it's roughly \(50^2 = 2500\times\) harder for the attention step. This is why long context windows were historically rare and pricey, and why an entire research industry exists to make attention cheaper (FlashAttention reorganises the computation to save memory; sparse, linear, and sliding-window attentions approximate the full \(n^2\) grid).

Training a transformer is otherwise familiar territory: we stack the blocks from Lesson 32, run the data forward, compute a loss, and backpropagate (Week 25) using an adaptive optimiser like Adam (Week 26). Residual connections (Week 29) and layer norm (Week 27) keep gradients healthy through dozens of layers. The transformer is wildly parallel — all \(n\) positions are processed simultaneously on the GPU — which is exactly what makes training on internet-scale data feasible. Which raises the next question: where do the labels come from?

33.3 Pre-training: learning from text with no labels

Here is the idea that turned transformers from a good translation model into the foundation of modern AI. Back in Week 12 we met self-supervised learning: the data labels itself. You hide part of the input and ask the model to predict the hidden part. No humans, no annotation — just oceans of raw text from the web, each sentence quietly generating its own training targets. This phase is called pre-training, and it comes in two famous flavours that map exactly onto the two halves of the transformer from Lesson 32.

Flavour 1 — Masked Language Modelling (BERT, the encoder)

BERT (2018) uses an encoder stack with unmasked self-attention, so every token can see the whole sentence — left and right. To train it, we randomly hide about 15% of the tokens with a special [MASK] symbol and ask the model to fill in the blanks:

The cat sat on the [MASK].  →  predict mat

Because it reads in both directions, BERT builds deep, context-rich representations of each word — perfect for understanding tasks like classification, sentiment, and question answering where you have the full text up front. It's a "fill-in-the-blank" reader, not a writer.

Flavour 2 — Next-Token Prediction (GPT, the decoder)

GPT uses a decoder stack with the causal mask from Lesson 32, so each token may only look backward. Its self-supervised task is the simplest imaginable: predict the next word, over and over, across all of the internet.

The cat sat on the ___  →  predict mat

That's it. A single objective — guess what comes next — applied to trillions of words. To predict the next word well, the model is quietly forced to learn grammar, facts, translation, arithmetic, and reasoning, because all of those help reduce the prediction error. This is the engine inside every LLM, and it's exactly what you'll build in Project 4. The whole training signal is just "next token," which makes GPT a natural writer: to generate, you predict the next word, append it, and repeat.

⚠️ Encoder vs decoder, don't mix them up

BERT = bidirectional encoder = fill in the blank = understanding. GPT = causal decoder = predict the next word = generation. Same transformer parts (Lesson 32), different masks and different self-supervised objectives. The mask is what makes one a reader and the other a writer.

Then: fine-tuning

Pre-training gives you a model that deeply understands language but isn't yet pointed at your specific task. The second phase, fine-tuning, takes that pre-trained model and continues training briefly on a small, labelled dataset for the job you actually care about — spam detection, medical Q&A, legal summarisation. This is the very transfer learning idea from Week 29 (where we fine-tuned a pre-trained ResNet on new images), now applied to language. The pre-trained model has already paid the enormous cost of learning what words mean; fine-tuning just nudges it toward your goal with a handful of examples.

33.4 Sinusoidal positional encoding in NumPy

Let's make the clock-wall concrete. The code below computes sinusoidal positional encodings for a short sequence and prints the resulting matrix, so you can see the columns oscillating at different frequencies.

numpy — sinusoidal positional encoding
import numpy as np

def positional_encoding(seq_len, d_model):
    """Build the (seq_len, d_model) sinusoidal PE matrix from the
    'Attention Is All You Need' formula."""
    pos = np.arange(seq_len)[:, None]          # column of positions: shape (seq_len, 1)
    i   = np.arange(d_model)[None, :]          # row of dim indices:  shape (1, d_model)

    # Frequency for each dimension. Even dims -> sin, odd dims -> cos,
    # and BOTH use the same angle, so we floor the index to pairs (2i).
    angle_rates = 1.0 / np.power(10000, (2 * (i // 2)) / d_model)
    angles = pos * angle_rates                 # (seq_len, d_model) — each entry is pos / 10000^(2i/d)

    PE = np.zeros((seq_len, d_model))
    PE[:, 0::2] = np.sin(angles[:, 0::2])      # even dimensions use sine
    PE[:, 1::2] = np.cos(angles[:, 1::2])      # odd  dimensions use cosine
    return PE

PE = positional_encoding(seq_len=6, d_model=8)
print("positional encoding matrix (6 positions, 8 dims):")
print(np.round(PE, 2))

# Each ROW is the unique "timestamp" vector added to a token at that position.
# Notice left columns oscillate FAST (high frequency), right columns oscillate
# SLOWLY — the 'wall of clocks' running at different speeds.

# Nearby positions are similar; far-apart positions are not.
def cos_sim(a, b):
    return a @ b / (np.linalg.norm(a) * np.linalg.norm(b))   # cosine similarity (Week 2)

print("sim(pos 0, pos 1):", round(cos_sim(PE[0], PE[1]), 3))   # high  -> neighbours look alike
print("sim(pos 0, pos 5):", round(cos_sim(PE[0], PE[5]), 3))   # lower -> far apart look different

Run it and you'll see the left-hand columns flip sign quickly from row to row while the right-hand columns drift slowly — the fast and slow clock hands. The two cosine similarities confirm the key property: neighbouring positions have similar encodings, distant ones do not, so the model can read "how far apart are these two words?" straight out of the geometry.

✅ Check Yourself

Why does a transformer need positional encoding at all?
Self-attention is permutation-equivariant — shuffle the words and you get the same (reordered) result. It has no built-in notion of position, so we add a positional vector to each embedding to restore word order.
A model's context length grows from 1,000 to 4,000 tokens. Roughly how does the attention cost change?
The score matrix QKᵀ is n × n, so cost scales with n². Multiplying n by 4 multiplies the cost by 4² = 16 — exactly why long context windows are expensive.
What is the key difference between how BERT and GPT are pre-trained?
Both are self-supervised (no human labels). BERT is a bidirectional encoder trained by masked-language modelling — fill in the blank. GPT is a causal decoder trained by next-token prediction — guess what comes next. The mask is what makes one a reader and the other a writer.
