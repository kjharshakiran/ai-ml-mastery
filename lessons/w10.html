Image, Video & Audio Processing: Pixels & Waveforms are Numbers Too

⏱️ 45 min🎯 Senses as tensors📦 Week 10

By the end of this lesson you'll be able to…

  • Name the three core vision tasks — classification, detection, segmentation — and place video as "images over time."
  • Understand sound as a 1-D waveform of samples, and how a spectrogram turns audio into an image.
  • Appreciate how the same pixel/tensor framing powers medicine, satellites, and more.

The Big Question
A photo, a movie clip, and a song feel completely different to us. To a machine they're all just numbers. What numbers, arranged how — and why does that make them ready for the very same maths we've already learned?

10.1 An image is a grid of numbers

Last lesson we turned words into vectors. Images are easier in one sense: they're born as numbers. Zoom into any digital photo far enough and you hit pixels — tiny coloured squares. Each pixel is a brightness value, usually an integer from 0 (black) to 255 (white).

A greyscale image is therefore a 2-D grid: height × width numbers. A colour image stacks three such grids — one each for Red, Green and Blue — so it's a 3-D block of numbers with shape (H, W, 3). Mix the three channels and you get any colour. That 3-D block is called a tensor: just a vector/matrix with more axes, exactly the objects from Lesson 2 grown an extra dimension.

🧒 Explain Like I'm 10

Think of a giant paint-by-numbers poster. Every little square has a number, and the number tells you how bright to colour it — 0 means "leave it black," 255 means "paint it brightest white." A photo on a computer is just one of those posters with a few million squares. And for colour, you stack three posters — a red one, a green one and a blue one — on top of each other. The computer never sees a "cat." It only ever sees the grid of numbers.

10.2 What we ask of images: the three vision tasks

Once an image is a tensor, computer vision asks three escalating questions:

  • Classification: "What is in this image?" → one label for the whole picture ("cat"). The simplest task.
  • Detection: "What is in it, and where?" → draw boxes around each object ("cat here, dog there"). Powers self-driving cars and face-finders.
  • Segmentation: "Which exact pixels belong to each thing?" → colour in every pixel by category. The most fine-grained, used in medical scans and photo-editing "select subject."

10.3 Video = images over time

A video adds one more axis: time. It's just a stack of images (frames) played fast enough — typically 24–30 per second — that our eyes blend them into motion. So a colour video clip is a 4-D tensor of shape (frames, H, W, 3). Every still-image task above still applies, plus new ones that need the time axis: action recognition ("is this person waving or falling?") and object tracking.

🎞️ Real-World Analogy

A video is an old-fashioned flip-book. Each page is a single drawing (an image tensor); flip them fast and a character seems to walk. The computer literally stores the flip-book as a tall stack of grids of numbers. Add the page-order (time) and you can ask not just "what's drawn?" but "what's happening?"

10.4 Audio: sound as a waveform of samples

Sound is a wave of air pressure wobbling over time. A microphone measures that pressure thousands of times a second — each measurement is a sample. CD-quality audio takes 44,100 samples per second (44.1 kHz). So a sound clip is simply a long 1-D list of numbers: amplitude versus time. Same golden rule again — audio is a vector of numbers.

But raw waveforms are hard to learn from directly. The clever move is the spectrogram: slide a window along the audio and, at each moment, use a Fourier transform to ask "how much of each pitch (frequency) is present right now?" Stack those answers and you get a 2-D image — time across the bottom, frequency up the side, brightness = loudness of that pitch.

This is a beautiful unification: by turning sound into a spectrogram image, the same models that recognise cats can recognise spoken words or a coughing patient. Speech-to-text, music tagging, and wake-word detection ("Hey Siri") all lean on this trick.

10.5 The same framing everywhere

Because every modality is "just a tensor of numbers," the same toolkit transfers across wildly different fields:

  • Medical imaging: an X-ray or MRI is a pixel grid; segmentation outlines a tumour, classification flags a fracture.
  • Remote sensing: a satellite photo is an image with extra channels (infrared, thermal) — sometimes a dozen — used to map deforestation or crop health.
  • Audio diagnostics & sonar, seismology, even particle physics: all reduce a signal to a tensor and ask a classification/detection question.
🔑 The one thing to remember

Text, images, video, audio — your machine never perceives any of them. It perceives tensors of numbers: a list (audio), a grid (image), a stack of grids (colour), a stack of stacks (video). Once everything is a tensor, one mathematical toolkit handles them all. That single idea is why a "vision" model and a "speech" model can share almost identical machinery.

python — an image is just a NumPy array
import numpy as np

# We'll build a tiny 4x4 RGB image by hand so the numbers are visible.
# Shape convention: (Height, Width, Channels). Channels = 3 for R, G, B.
img = np.zeros((4, 4, 3), dtype=np.uint8)   # all-black image (every value 0)

img[0, 0] = [255,   0,   0]   # top-left pixel -> pure RED
img[0, 3] = [  0, 255,   0]   # top-right     -> pure GREEN
img[3, 0] = [  0,   0, 255]   # bottom-left   -> pure BLUE
img[3, 3] = [255, 255, 255]   # bottom-right  -> WHITE (all channels max)

print(img.shape)        # -> (4, 4, 3)   height=4, width=4, 3 colour channels
print(img.dtype)        # -> uint8       values are integers 0..255
print(img[0, 0])        # -> [255 0 0]   the red pixel's three numbers

# Models prefer small floats, so we NORMALISE pixels from 0..255 to 0..1
img_norm = img.astype(np.float32) / 255.0
print(img_norm[3, 3])   # -> [1. 1. 1.]  white is now (1,1,1)
print(img_norm.min(), img_norm.max())   # -> 0.0 1.0  (range is now [0,1])

# A real photo loads the same way and is just bigger:
#   from PIL import Image
#   arr = np.asarray(Image.open("cat.jpg"))   # e.g. shape (480, 640, 3)
# It's still nothing but a grid of numbers.

Notice what we just did. Normalising — rescaling pixels from \([0, 255]\) to \([0, 1]\) — is the same standardisation idea you'll meet formally in Week 19, and it makes training far more stable. The image went in as a picture and came out as an ordinary array we can add, scale, and dot-product, exactly like the vectors in Lesson 2.
