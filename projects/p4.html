Mini-GPT — Build a Language Model from Scratch

🔴 Difficulty: Advanced🎯 From a vector to a thinking machine🧰 PyTorch · Embeddings · Self-Attention · Transformer

What you'll build

  • A complete character-level GPT in ~120 lines of PyTorch — every tensor by hand.
  • A tokeniser, an embedding table, and a positional encoding.
  • Masked multi-head self-attention — the single idea behind ChatGPT — commented line by line.
  • Transformer blocks with residual connections and layer norm, plus a training loop on next-token cross-entropy.
  • A generate() function that samples new text one character at a time.
The Big Question
How can a model that only ever learns to predict the next character end up writing coherent sentences, code, and poetry? And what is "attention," really, underneath the hype?

This is where the whole course converges. Way back in Week 2 we said "everything becomes a vector." Now watch the full through-line snap into place: vectors (W2) → embeddings (W31) → attention (W32) → pre-training (W33) → generation (W34). Each arrow is a section below, and each is just tensors and the gradient descent you already know.

🧒 Explain Like I'm 10

It's the world's best "guess the next letter" game. You show the model tons of text and it learns: after "to be or not to b", the next letter is almost certainly "e". Do that billions of times and to guess well it has to understand grammar, names, and ideas — there's no other way to keep winning. To write something new, it just guesses the next letter, adds it, and guesses again, over and over. "Attention" is how it decides which earlier words matter most for the next guess — like glancing back at the question while answering.

The Mini-GPT forward pass

Step 1 — Tokenise the text (vectors, W2)

We work at the character level: every distinct character gets an integer id. That's the simplest possible tokeniser, and it makes the rest crystal clear.

step1_tokenise.py
import torch

# Any text works; a Shakespeare or tiny-stories .txt is the classic choice.
text = open("input.txt").read()           # e.g. ~1MB of Shakespeare

chars = sorted(set(text))                  # the vocabulary
vocab_size = len(chars)
stoi = {c: i for i, c in enumerate(chars)} # char -> id
itos = {i: c for c, i in stoi.items()}     # id   -> char

encode = lambda s: [stoi[c] for c in s]
decode = lambda ids: "".join(itos[i] for i in ids)

data = torch.tensor(encode(text), dtype=torch.long)
n = int(0.9 * len(data))
train_data, val_data = data[:n], data[n:]
print(vocab_size, "unique chars;", len(data), "tokens total")

Step 2 — Embeddings + positional encoding (W31, W33)

An integer id carries no meaning. An embedding table (Week 31) maps each id to a learnable dense vector — the model's evolving notion of what that token "means," exactly the idea from Project 2's upgrade. But attention (next step) is order-blind, so we also add a positional embedding (Week 33) so the model knows where each token sits.

🔑 Two vectors, added

Each position in the input gets token embedding + position embedding. The token vector says "what word"; the position vector says "where in the sentence." Their sum is a single vector that encodes both — and that sum is what flows into the transformer. This is the literal handshake between Week 31 (embeddings) and Week 33 (positional encoding).

Step 3 — Masked multi-head self-attention (W32)

Here is the idea that changed AI. For each token, attention builds three vectors: a query ("what am I looking for?"), a key ("what do I offer?"), and a value ("what I'll pass on if chosen"). A token's new representation is a weighted average of all values, where the weights come from how well its query matches each key — a dot product (Week 2!):

\[ \text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}} + M\right)V \]

The mask \(M\) sets future positions to \(-\infty\) so a token can only attend to itself and earlier tokens — that's what makes it a causal language model that can generate left-to-right.

🔦 Real-World Analogy

Picture a meeting where everyone needs context to speak. Each person raises a query ("I need info about the budget"). Everyone else holds up a key labelling what they know. You listen most to the people whose keys best match your query, and you absorb their values (what they actually say). Self-attention is every word in a sentence doing this simultaneously — and the masking means you can only listen to people who spoke before you.

step3_attention.py — heavily commented
import torch.nn as nn
import torch.nn.functional as F

class MultiHeadAttention(nn.Module):
    """Causal (masked) multi-head self-attention -- the engine of a GPT."""
    def __init__(self, n_embd, n_head, block_size, dropout=0.1):
        super().__init__()
        assert n_embd % n_head == 0
        self.n_head = n_head
        self.head_dim = n_embd // n_head            # each head works in a subspace

        # One big linear projects each token into Q, K, V at once (3*n_embd).
        self.qkv = nn.Linear(n_embd, 3 * n_embd, bias=False)
        self.proj = nn.Linear(n_embd, n_embd)       # mixes heads back together
        self.drop = nn.Dropout(dropout)

        # Lower-triangular mask: position t may attend to 0..t only (no peeking ahead).
        mask = torch.tril(torch.ones(block_size, block_size))
        self.register_buffer("mask", mask.view(1, 1, block_size, block_size))

    def forward(self, x):
        B, T, C = x.shape                           # batch, time(=seq len), channels

        # Project to queries, keys, values and split into heads.
        q, k, v = self.qkv(x).split(C, dim=2)       # each (B, T, C)
        # reshape (B,T,C) -> (B, n_head, T, head_dim) so heads run in parallel
        q = q.view(B, T, self.n_head, self.head_dim).transpose(1, 2)
        k = k.view(B, T, self.n_head, self.head_dim).transpose(1, 2)
        v = v.view(B, T, self.n_head, self.head_dim).transpose(1, 2)

        # Attention scores = query . key  (how relevant is each token to each other)
        att = (q @ k.transpose(-2, -1)) / (self.head_dim ** 0.5)   # (B,nh,T,T)

        # CAUSAL MASK: forbid attending to the future by setting it to -inf,
        # so after softmax those weights become exactly 0.
        att = att.masked_fill(self.mask[:, :, :T, :T] == 0, float("-inf"))
        att = F.softmax(att, dim=-1)                # weights sum to 1 over the past
        att = self.drop(att)

        # Weighted sum of VALUES -> each token's context-aware new vector.
        out = att @ v                               # (B, nh, T, head_dim)
        out = out.transpose(1, 2).contiguous().view(B, T, C)  # re-merge heads
        return self.proj(out)                       # final linear mix

Step 4 — A transformer block

One block = attention (tokens talk to each other) + an MLP (each token thinks on its own), each wrapped in a residual connection and layer norm. Residuals let gradients flow through deep stacks (the ResNet trick from Project 3); layer norm keeps activations well-scaled.

step4_block.py
class Block(nn.Module):
    def __init__(self, n_embd, n_head, block_size):
        super().__init__()
        self.ln1 = nn.LayerNorm(n_embd)
        self.attn = MultiHeadAttention(n_embd, n_head, block_size)
        self.ln2 = nn.LayerNorm(n_embd)
        self.mlp = nn.Sequential(                   # per-token feed-forward
            nn.Linear(n_embd, 4 * n_embd),
            nn.GELU(),
            nn.Linear(4 * n_embd, n_embd),
            nn.Dropout(0.1),
        )

    def forward(self, x):
        # Pre-norm residuals: x = x + sublayer(norm(x)). Add, never overwrite.
        x = x + self.attn(self.ln1(x))              # tokens exchange information
        x = x + self.mlp(self.ln2(x))               # each token processes alone
        return x

Step 5 — Assemble the GPT (W31 → W34 in one class)

Embeddings, a stack of blocks, a final norm, and a linear head that scores every vocabulary character. Feed in a length-T context, get back logits for the next character at each position.

step5_gpt.py
class MiniGPT(nn.Module):
    def __init__(self, vocab_size, n_embd=128, n_head=4, n_layer=4, block_size=128):
        super().__init__()
        self.block_size = block_size
        self.tok_emb = nn.Embedding(vocab_size, n_embd)    # token meaning  (W31)
        self.pos_emb = nn.Embedding(block_size, n_embd)    # position info  (W33)
        self.blocks  = nn.Sequential(*[Block(n_embd, n_head, block_size)
                                       for _ in range(n_layer)])
        self.ln_f = nn.LayerNorm(n_embd)
        self.head = nn.Linear(n_embd, vocab_size)          # -> score per char (W34)

    def forward(self, idx, targets=None):
        B, T = idx.shape
        pos = torch.arange(T, device=idx.device)
        x = self.tok_emb(idx) + self.pos_emb(pos)          # add the two embeddings
        x = self.blocks(x)                                 # N transformer blocks
        logits = self.head(self.ln_f(x))                   # (B, T, vocab_size)

        loss = None
        if targets is not None:
            # Next-token prediction: each position predicts the FOLLOWING char.
            loss = F.cross_entropy(logits.view(-1, logits.size(-1)),
                                   targets.view(-1))
        return logits, loss

Step 6 — Pre-train on next-token prediction (W33)

"Pre-training" sounds grand but it's just our familiar loop (Weeks 25–26): grab a random chunk, ask the model to predict each next character, measure cross-entropy, backpropagate. That single self-supervised objective is how every LLM learns language — no labels, just the text predicting itself.

step6_pretrain.py
device = "cuda" if torch.cuda.is_available() else "cpu"
block_size, batch_size = 128, 32
model = MiniGPT(vocab_size, block_size=block_size).to(device)
opt = torch.optim.AdamW(model.parameters(), lr=3e-4)

def get_batch(split):
    d = train_data if split == "train" else val_data
    ix = torch.randint(len(d) - block_size, (batch_size,))   # random start points
    x = torch.stack([d[i:i+block_size]     for i in ix])     # context
    y = torch.stack([d[i+1:i+block_size+1] for i in ix])     # context shifted by 1
    return x.to(device), y.to(device)

for step in range(3000):
    xb, yb = get_batch("train")
    _, loss = model(xb, yb)        # forward + loss
    opt.zero_grad()
    loss.backward()                # backprop through attention & embeddings
    opt.step()                     # AdamW update
    if step % 500 == 0:
        print(f"step {step:4d}  train loss {loss.item():.3f}")
# Loss falls from ~4.2 (random over vocab) toward ~1.5 -- the model is
# learning Shakespeare's character statistics from nothing but the text.

Step 7 — Generate by sampling (W34)

Generation is the forward pass run in a loop: feed the context, softmax the final logits into a probability distribution over the next character, sample one, append it, repeat. Sampling (rather than always taking the argmax) is what gives the output variety and life.

step7_generate.py
@torch.no_grad()
def generate(model, idx, max_new_tokens, temperature=1.0):
    model.eval()
    for _ in range(max_new_tokens):
        idx_cond = idx[:, -model.block_size:]        # never exceed context window
        logits, _ = model(idx_cond)
        logits = logits[:, -1, :] / temperature      # take the LAST step's scores
        probs = F.softmax(logits, dim=-1)            # -> distribution over vocab
        next_id = torch.multinomial(probs, 1)        # SAMPLE the next char
        idx = torch.cat([idx, next_id], dim=1)       # append & continue
    return idx

start = torch.zeros((1, 1), dtype=torch.long, device=device)  # seed token
out = generate(model, start, max_new_tokens=400)[0].tolist()
print(decode(out))   # -> Shakespeare-flavoured text, invented one char at a time

🚀 Make it your own

  • Add temperature & top-k. Lower temperature → safe, repetitive text; higher → wild. Top-k truncation keeps samples coherent.
  • Scale it up. More layers, heads and a bigger n_embd on a GPU; watch the validation loss to avoid overfitting.
  • Switch to BPE tokens. Replace the char tokeniser with tiktoken so the model learns sub-words like a real GPT.
  • Visualise attention. Plot one head's attention matrix and literally see which earlier characters it looks back at.
  • Fine-tune it. Pre-train on a large corpus, then fine-tune on your own text (your emails, a codebase) to give it a voice.
