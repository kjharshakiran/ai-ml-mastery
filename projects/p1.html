🏆 Capstone Project 1

The Tabular ML Pipeline

🟢 Difficulty: Foundational🎯 The full classical-ML workflow🧰 EDA · Regression · Trees · Ensembles · PCA · k-Means

What you'll build

  • A complete, reproducible pipeline that goes from a raw table to insight + predictions.
  • An EDA pass that listens to the data: describe(), missing-value audit, correlation heatmap.
  • A preprocessing stage that scales numbers and encodes categories the right way (fit on train only).
  • A model bake-off: Logistic Regression vs Decision Tree vs Random Forest, judged with accuracy, precision, recall and a confusion matrix.
  • An unsupervised finale: PCA to compress and visualise, then k-Means to discover natural groups.
The Big Question
Given nothing but a spreadsheet of rows and columns, how do professionals turn it into a trustworthy model — and how do they know which model to trust?

This is the project every working data scientist runs in their sleep. We'll use the classic Iris dataset (150 flowers, 4 measurements, 3 species) because it's small enough to see end-to-end yet rich enough to exercise every step you learned in Parts 1–4. The same skeleton scales unchanged to Titanic, California housing, or your company's churn table — only the columns change.

🧒 Explain Like I'm 10

Imagine a box of mixed flowers and a ruler. You measure each flower, write the numbers in a notebook, and notice "the ones with long skinny petals are always the same kind." A computer does exactly this, just faster: it reads the measurement notebook, finds the patterns, and then guesses the species of a brand-new flower it has never seen. This project is teaching the computer to be that flower-guesser — and then checking how often it's right.

The pipeline at a glance

Every tabular project flows through the same seven stations. Keep this map in your head; the code below is just each box made real.

Step 1 — Load the data & run EDA

Exploratory Data Analysis (Week 8) is where you listen before you model. Three questions answer 90% of "is this data healthy?": what do the columns look like (describe), is anything missing, and which features move together (corr)?

step1_eda.py
import numpy as np
import pandas as pd
from sklearn.datasets import load_iris

# Load the classic Iris dataset as a tidy DataFrame.
iris = load_iris(as_frame=True)
df = iris.frame                      # 4 feature columns + a 'target' column (0/1/2)
df["species"] = df["target"].map(dict(enumerate(iris.target_names)))

print(df.shape)                      # -> (150, 6)
print(df["species"].value_counts()) # -> 50 of each class: perfectly balanced

# --- EDA question 1: what do the numbers look like? ---
print(df.describe())                 # count, mean, std, min, quartiles, max per column

# --- EDA question 2: is anything missing? ---
print(df.isna().sum())               # -> all zeros here; on real data, this is gold

# --- EDA question 3: which features move together? ---
corr = df[iris.feature_names].corr() # Pearson correlation matrix (-1..1)
print(corr.round(2))
# petal length & petal width correlate ~0.96 -> they carry near-identical info.
# That redundancy is exactly what PCA (Step 5) will exploit.
🔑 Read the correlation matrix like a pro

Two features correlated near \(\pm 1\) are nearly redundant — they're almost the same column wearing different hats. High correlation hints that the data secretly lives in fewer dimensions than it has columns, which is the entire premise of PCA in Step 5. Correlation is just the dot product of two mean-centred, normalised columns — the linear algebra from Week 2 made practical.

Step 2 — Preprocess: scale & split

Models that measure distance (k-NN, k-Means) or use gradient descent (logistic regression) are sensitive to scale. A feature measured in centimetres shouldn't dominate one measured in millimetres just because its numbers are bigger. We standardise to mean 0, variance 1 (Week 19):

\[ z = \frac{x - \mu}{\sigma} \]

⚠️ The cardinal sin: data leakage

Always fit the scaler on the training set only, then transform both sets. If you fit on all the data, your test set has secretly peeked at the training statistics and your scores will be optimistically wrong. Split first, scale second.

step2_preprocess.py
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

X = df[iris.feature_names].values    # (150, 4) feature matrix
y = df["target"].values              # (150,)   integer labels 0/1/2

# Split FIRST so the test set stays a true unseen sample.
# stratify=y keeps the 3 classes balanced in both halves.
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=42, stratify=y)

# Fit the scaler on TRAIN ONLY, then apply to both. No leakage.
scaler = StandardScaler().fit(X_train)
X_train_s = scaler.transform(X_train)
X_test_s  = scaler.transform(X_test)

print(X_train_s.mean(axis=0).round(2))  # ~[0 0 0 0]  (centred)
print(X_train_s.std(axis=0).round(2))   # ~[1 1 1 1]  (unit variance)

# NOTE on encoding: Iris is all-numeric. For a dataset with categorical
# columns (e.g. Titanic's 'Sex', 'Embarked') you would one-hot encode them:
#   from sklearn.preprocessing import OneHotEncoder
#   OneHotEncoder(handle_unknown="ignore").fit_transform(cat_cols)

Step 3 — Train three models

We pit three workhorses against each other. Each makes a different bet about the world, and seeing them side by side builds your instinct for which to reach for:

  • Logistic Regression (Week 13/25) — draws straight decision boundaries. Fast, interpretable, a great baseline.
  • Decision Tree (Week 21) — asks a cascade of yes/no questions. Captures non-linear rules; prone to overfitting.
  • Random Forest (Week 22) — a committee of many trees that vote. Usually the strongest off-the-shelf tabular model.
🌳 Real-World Analogy

A single decision tree is one opinionated expert who can be confidently wrong. A random forest is a room full of experts, each shown a slightly different slice of the evidence, then taking a vote. The crowd's average cancels out individual quirks — that's why ensembles (Week 22) so reliably beat any one model.

step3_train.py
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier

models = {
    "Logistic Regression": LogisticRegression(max_iter=200),
    "Decision Tree":       DecisionTreeClassifier(max_depth=3, random_state=42),
    "Random Forest":       RandomForestClassifier(n_estimators=200, random_state=42),
}

# .fit() learns the parameters from the scaled training data.
for name, model in models.items():
    model.fit(X_train_s, y_train)
    print(f"{name:22s} trained.")

Step 4 — Evaluate: accuracy, precision, recall, confusion matrix

Accuracy alone lies on imbalanced data. The full picture (Week 15) needs precision ("when the model says class A, how often is it right?") and recall ("of all the true class-A items, how many did it catch?"):

\[ \text{precision}=\frac{TP}{TP+FP},\qquad \text{recall}=\frac{TP}{TP+FN} \]

The confusion matrix shows exactly which classes get mixed up — its diagonal is correct predictions, off-diagonal are the mistakes.

step4_evaluate.py
from sklearn.metrics import (accuracy_score, classification_report,
                             confusion_matrix)

for name, model in models.items():
    y_pred = model.predict(X_test_s)
    acc = accuracy_score(y_test, y_pred)
    print(f"\n=== {name} (accuracy={acc:.3f}) ===")

    # Per-class precision / recall / F1 in one tidy table.
    print(classification_report(y_test, y_pred,
                                target_names=iris.target_names))

    # Rows = true class, columns = predicted class. Diagonal = correct.
    print("Confusion matrix:\n", confusion_matrix(y_test, y_pred))

# On Iris you'll see all three models hit ~0.95-1.00 accuracy.
# The only confusions are between versicolor & virginica -- the two
# species whose petals overlap. setosa is linearly separable and never missed.
#
# REGRESSION NOTE: on a numeric-target dataset (e.g. California housing)
# you'd swap to LinearRegression / RandomForestRegressor and score with RMSE:
#   from sklearn.metrics import mean_squared_error
#   rmse = mean_squared_error(y_test, y_pred, squared=False)

Step 5 — PCA: compress 4D to 2D and look

We have 4 features — impossible to plot directly. PCA (Week 20) finds the directions of greatest variance (the top eigenvectors of the covariance matrix — straight from Week 2) and projects onto the best two, so we can see the data with our own eyes while keeping most of the information.

step5_pca.py
from sklearn.decomposition import PCA
import matplotlib.pyplot as plt

# Reduce 4 features -> 2 principal components on the scaled data.
pca = PCA(n_components=2).fit(X_train_s)
X_train_2d = pca.transform(X_train_s)

# How much information did we keep? (variance captured by each PC)
print(pca.explained_variance_ratio_)        # ~[0.73, 0.23]
print(pca.explained_variance_ratio_.sum())  # ~0.96 -> 2 dims hold 96% of the signal!

plt.figure(figsize=(6, 5))
for cls, name in enumerate(iris.target_names):
    pts = X_train_2d[y_train == cls]
    plt.scatter(pts[:, 0], pts[:, 1], label=name, alpha=0.8)
plt.xlabel("PC 1"); plt.ylabel("PC 2"); plt.legend(); plt.title("Iris in 2D via PCA")
plt.tight_layout(); plt.savefig("iris_pca.png", dpi=120)
# The plot shows setosa floating off alone; versicolor & virginica touching.
# Exactly the structure the confusion matrix predicted -- now made visible.

Step 6 — k-Means: discover groups with no labels

Final twist: forget the labels. Can the data find its own groups? k-Means (Week 23) places \(k\) centroids and iterates "assign each point to the nearest centroid, then move each centroid to the mean of its points" until things settle. We ask for \(k=3\) and check whether the clusters it invents match the real species.

step6_kmeans.py
from sklearn.cluster import KMeans
from sklearn.metrics import adjusted_rand_score

# Cluster the FULL scaled dataset -- unsupervised, labels never touched.
X_all = scaler.transform(X)                 # reuse the train-fitted scaler
km = KMeans(n_clusters=3, n_init=10, random_state=42).fit(X_all)
clusters = km.labels_

# Adjusted Rand Index compares the discovered clusters to the true species.
# 1.0 = perfect agreement, 0.0 = random. (Cluster *numbers* won't match
# class numbers, but ARI is invariant to relabelling.)
ari = adjusted_rand_score(y, clusters)
print(f"Adjusted Rand Index: {ari:.3f}")    # ~0.62 -> structure recovered well
# k-Means rediscovers setosa cleanly and roughly separates the other two,
# all without ever seeing a single label. That is unsupervised learning.

  • Swap the dataset. Re-run the whole pipeline on Titanic (add one-hot encoding for Sex/Embarked) or California housing (switch to regressors + RMSE). The skeleton barely changes — that's the point.
